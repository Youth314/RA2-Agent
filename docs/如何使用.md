# 如何使用

怎么把一局跑起来、怎么让人与 Agent 同桌、出问题去哪儿看。开发环境、焦点与留证见[真机测试手册](../.agents/notes/真机测试手册.md)；设计原理见[架构设计](../.agents/notes/架构设计.md)、[技法框架](../.agents/notes/技法框架.md)、[指挥层](../.agents/notes/指挥层.md)。

## 起一局

一局对战是**多个游戏进程**，不是多个调用方连同一个进程；`-SPAWN` 不进大厅也不等对手，故必须按名册一次起全。

```sh
python3 tools/start_match.py up        # 按名册渲染 spawn.ini、起全、等到每一方都进对局
python3 tools/start_match.py status    # 逐参与者看进程、端口、阶段、帧
python3 tools/start_match.py down      # 按 PID 停，不会误伤另一方
```

名册与规则在 `config/match.json`：`players` 是部署事实（名字、游戏目录、探针端口、对局端口、`Side`、`Color`），`rules` 是每局的选择（地图、资金、科技等级、迷雾、箱子、席位）。加人只能加在名册里；临时改规则用 `--rule key=value`，别手改渲染出来的 `spawn.ini`（`up` 每次会重渲染，原文件留成 `.render-bak`）。换地图受限：`rules.scenario` 要指向一份已备好的地图文件。

## 让谁上桌

三种参与者可自由组合：

- **Agent**：`play_as_alpha` / `play_as_beta` 各建一个玩家 agent，各自一份 MCP 客户端连自己那一侧的游戏实例——**隔离是构造上的**，对手的工具它看不到也调不到。派遣是异步的，之后用 `send_message` 追加任务。
- **人**：不起玩家 agent，自己操作那个窗口即可；名册里那一方的席位照样存在。
- **游戏内置电脑**：在 `rules` 里配 `ai_players` 与 `ai_difficulty`。

**主持 agent 在信任边界之外**：它手里也有游戏工具（连名册里第一方），因为它要用 `game` 看进程；它不该替任何一方下令。

## Agent 在局内看到什么

五个工具：`status`（读局势）、`tactics`（当前可用技法卡片）、`call`（下达任务）、`cancel`（撤销在管任务）、`game`（起停游戏、看进程与焦点）。**没有任何直接向引擎下命令的工具**，一切动作都经技法层与 `Validator`。卡片与事件上报的形状见[指挥层](../.agents/notes/指挥层.md)。

模型平时不在场，出事了才被叫回来：事件（掉单位、断电、被渗透、出局、建筑完工待放置）触发唤醒，经 DSH 的本地路由投成一条 user 消息。链路细节与节制见[指挥层](../.agents/notes/指挥层.md#叫醒模型)。

## 盯局与验收

- **看进程与焦点**：`game status` 报进程、端口、崩溃留证与**按帧号判的**主循环状态；窗口不在前台不等于暂停。
- **看局势**：`status` 报一行摘要、本局信息、电力、生产、待放置与可选落点、可造清单、单位与敌方、在管任务、新结果与新事件。**新结果读走即清**。
- **常驻监听**：`PYTHONPATH=src python3 -m ra2agent.watch --player <名册名> --wake-session <agent id>`，只读局势、按同一份判据挑事件、投唤醒，用于模型空闲期间的叫醒。

验收一局的方法与判据见[真机测试手册](../.agents/notes/真机测试手册.md#五点七验收一条链路)。
