# 玩家操作能力表

调查日期：2026-10-02。基准为 Steam 安装中的官方 RA2/YR 手册、YR 1.001 原版 `rulesmd.ini`、已下载的固定提交源码和本项目实测记录。静态调查已完成；S2 首轮限定原版人工操作对照已收尾，证据与未测边界见下文“S2 现场记录”。尚未实现新基础接口，未修改 DLL 或业务代码。完整版本与许可边界见[引擎接口复用评估](引擎接口复用评估.md)，来源指纹见 [sources.json](../../tmp/player-capabilities/sources.json)。

## 已确认的设计约束

模型的游戏动作只经技法下达。基础玩家操作本身可以成为模型可调用的技法；组合技法通过这些基础能力表达侦察、推进、护送、采矿管理等任务。技法是否复杂不决定它能否公开。引擎内部的原始 Mission、地址和任意事件注入不直接开放给模型。

能力基准是玩家可表达的操作及原版规则下的效果。通用操作不保证对所有单位有相同效果；接口应结合单位类型、武器/乘员/部署状态、目标类别和阵营判断适用性。引擎完成原生寻路、自动选敌、采矿往返、维修和部署等行为，技法无需默认逐拍模拟这些行为。

表中的技法名和接口字段均为建议，不代表已实现。现有实现、上游路径、官方说明和本项目实测分别记录；“能发出消息”不代表“已实现玩家等价操作”。

## 1. 通用单位操作

基础技法应允许显式点名多单位，按单位独立返回接受/拒绝及原因。目标对象使用 Agent 稳定 ID，地点使用合法地图格；目标地图格不必已探索，因为真实玩家能命令单位前往未探索地点，但隐藏对象不能作为合法点名目标。执行模式、目标合法性和单位实际能力须另行验证。

| ID / 玩家操作 | 输入及原版含义 | 单位差异与限制 | 当前状态与映射 | 建议基础技法 | 生效/结果判据与依据 |
|---|---|---|---|---|---|
| U01 Move | 对单位下达目的地，交给原版寻路 | 地面、飞行、海军、两栖、悬浮和传送移动不同；部署/禁用状态影响可动性 | 已有 `UnitOrder.MOVE`；`advance_to_cell` 默认展开队形，且地面通行门不能覆盖所有单位 | `move` | 接受目的地与开始执行；到达另作任务结果，不要求精确占住同一格；M-RA2/E/L |
| U02 Attack Move | 前往目的地，沿途由游戏自动接敌 | 无武器、支援武器、射程/目标限制、返航等需逐类核验；非固定选最近敌人 | 部分：`ATTACK_MOVE` 已有，`advance_to_cell(aggressive)` 使用此路，实测有追敌偏离目标 | `attack_move` | 目标目的地/任务变化；接敌及后续继续前进单独记录；M-YR/E/L |
| U03 Stop，S | 停止当前移动/动作 | 不保证永不自动开火、永不再次采矿或永久固定位置 | 已有 `STOP`，`hold_position` 与隐藏的 `halt` 都落到它 | `stop` | 当前命令被停止；不把永久禁火/驻守当成已承诺效果；M-YR/E/L |
| U04 Guard Current Area，G | 启动玩家主动警戒 | 矿车/维修 IFV 等可能改为各自自动工作；追击、返回锚点和扫描对象依单位决定 | 缺失正式技法；S2 已在 Grizzly Battle Tank 观察到玩家 G 的 `MegaMission(AREA_GUARD)` 和当前位置 target，其他单位与自主接敌仍待测 | `guard` | 原版任务、警戒锚点与自主行为；不能用 STOP 或自选敌循环代替并宣称等价；M-RA2/M-YR/E/U |

| U06 Escort Unit，Ctrl+Alt 单位 | 随被护送单位移动并保护它 | 是否可护送盟友、距离、原版掉队/路径表现、跟随对象死亡后行为待测 | 缺失；S2 在 Grizzly Battle Tank 观察到 `AREA_GUARD + 对象 target` 并自行跟随，follow RTTI=0；不能仅按字段名映射 Escort | `escort_unit` | follow/目标回读及双方移动；不能只用固定地点警戒解释；M-YR/E |
| U07 Guard a Structure，Ctrl+Alt 建筑 | 围绕指定建筑执行保护 | 建筑状态、距离、失去归属/被毁、目标是否盟友待测 | 缺失；S2 在 Grizzly Battle Tank 观察到 `AREA_GUARD + 建筑 target` 并靠近己方建筑，防御接敌仍待测 | `guard_structure` | 目标身份与警戒行为；M-YR/E |
| U08 Attack object | 指定对象，由原版选择武器并执行攻击 | 攻击可为伤害、控制、抹除、吸引、爆破等；不能统一用掉血判定 | 部分：`ATTACK` 可发；`focus_fire` 有追到即结算和目标缓存问题 | `attack_target` | 当前目标匹配且原版动作生效；目标任务效果另外判；M-RA2/M-YR/R/E/L |

| U10 Force Move，Alt | 强制移动或执行可碾压目标的移动 | 是否可碾压由规则和单位决定；不能令所有载具碾压所有步兵 | 缺失修饰语义；普通 MOVE 不证明等价 | `force_move` | 目的地和实际路径/碾压行为；M-YR/R/E |
| U11 Scatter，X | 将所选单位分散 | 单位是否可散开、方向及可通行性由原版处理 | 候选：`ClickEvent` 可传 Scatter，未验且无技法 | `scatter` | 指令受理及分散位移，按混合单位报告拒绝；M-YR/E |
| U12 Deploy，D/部署光标 | 执行单位原版部署或第二功能 | MCV 变建筑；E1/GGI 武器姿态；DESO/YURI 能力；SCHP、SMIN 等另有状态 | 部分：Deploy 事件已测 MCV；`deploy_mcv` 专用，不代表其他类型已支持 | `deploy` | 按单位观察部署、武器/能力/乘员状态；不能一律以旧指针消失判成功；M-YR/R/E/L |
| U13 Undeploy / Unload / Evacuate | 玩家解除部署、卸载乘员或撤出驻军 | 有的使用 D，但这三种效果不同；IFV gunner、运输工具和驻军不能同判 | 缺失正式覆盖；现有 Deploy 指针消失谓词不能通用 | 按实际语义提供 `undeploy`、`unload`、`evacuate` | 乘员出现在地图、载体数量变化或部署解除；不能用乘员消失当死亡；M-YR/R/E |
| U14 Enter / interact object | 按单位与目标触发进入、装载、占领、维修、渗透等上下文动作 | 同一目标点击对不同单位对应不同 Action；满载、归属、驻军资格等会拒绝 | 部分：CAPTURE 原始命令有，其他上下文动作无正式意图 | `enter` 及有清晰用途的基础技法 | 回读 transporter、占领归属、乘员/驻军、渗透效果；M-RA2/M-YR/R/E |
| U15 Context action query | 查询这批单位对目标/地点可做什么，再按明确操作执行 | 查询必须尊重当前可见性与单位动态状态 | 缺失；有 `MouseOverCell/Object`、`DecideAction`、`Object/CellClickedAction` 的线索 | `available_actions`（查询技法，是否作为卡片元数据待设计） | 不能读取隐藏目标；需证明查询无游戏修改且不依赖脏的全局按键/选择状态；E |

U15 不要求增加第六个模型工具；可在现有 `status/tactics` 中展示动态适用能力，或经返回信息的查询技法实现，具体契约待设计。原生 MouseOver 方法不等于稳定无副作用 API，必须先核验调用条件。

## 2. 路径、计划与连续指令

| ID / 玩家能力 | 玩家可表达的内容 | 当前能力 | 建议形态 | 必须验证 |
|---|---|---|---|---|
| P01 Way Points，Z | 一组单位按顺序执行路点，计划期间等待提交 | 缺失原版路径；当前 MoveTo 是一个目标格，多次 call 不构成命令排队 | `follow_path` 基础技法，路点与各段操作显式记录 | 节点顺序、是否覆盖前令、节点推进及跨单位差异；M-RA2/E |
| P02 Loop / Patrol | 闭合路点形成持续巡逻，途中接敌 | 缺失原版路径；`scout_area` 是另一个选未知格的组合策略 | `patrol_path` | 闭环、接战后的恢复、退出方式和巡逻锚点；M-RA2/E |
| P03 Coordinated plans | 多组分别设置路径，最后提交使各组开始执行 | 缺失；`call(calls)` 批量受理不保证同帧执行/原子成功 | 技法内部的计划构造与提交；是否允许跨 call 持有计划待设计 | 待提交时单位保持原状态、取消、部分单位失效、实际提交帧；M-RA2/E |
| P04 Replace / append / clear | 明确新命令替换当前任务还是加入已有计划 | 原版 Z 计划有依据；任意动作通用 append 尚未确认。当前层有单位租约，但无正式玩家命令队列 | 先支持已验证的路径语义；通用 `queue_mode` 属建议 | 不假定 Shift 点击是任意排队；不假定 QMove 是通用 append；M-RA2/M-YR/E |
| P05 混合节点 | 路点结束接攻击/进入等上下文行为 | YRpp 有 AttackWaypoint、EnterWaypoint、PatrolWaypoint，能表达哪些序列需测 | `follow_path` 节点类型白名单，不开放任意 Mission | 攻击目标失去视野、装载中断、消耗单位、节点完成条件；E |
| P06 避障与通行 | 玩家指定目的地/路点，游戏负责局部路径 | 原版 MOVE 已寻路，但本项目统一地面格校验过窄；展开队形还主动改了目标 | 基础 move 默认忠实目标；队形/绕路放组合技法 | 空中、海军、悬浮/两栖、坡桥、障碍、目标格被占；M-RA2/R/E/L |

M-RA2 正式描述路点、循环巡逻和多组计划；M-YR 还指出其他单位不能合并到 Planning Mode plans，并限制非爆破步兵参与 Tanya 爆破路点。不能照搬 RA2 的旧技巧到 YR 1.001，也不能把普通 Python list 自动认作原版计划。

YRpp 的 `PlanningTokenClass`、`PlanningNodeClass`、`FootClass::PlanningPathIdx/WaypointIndex` 及 PlanConnect/PlanCommit/PlanNodeDelete 事件说明原版存在独立规划系统，但部分字段未知。`Event.MegaMission` 虽含 follow/is_planning_event，ra2yrcpp 的 `add_event()` 没有构造该载荷；它能解析历史事件不代表能正确创建事件。

可先实现由运行时按到位结果逐段下令的 `follow_path`，但必须标明该实现使用运行时调度；其提交时序、离线继续执行、接战恢复和单位队形与原版计划不同，不可承诺等价。原版计划作为单独能力继续测绘。

## 3. 相同操作在不同单位上的效果

| 对象/状态 | 共同操作与效果 | 本调查确认程度 | 对接口与技法的要求 |
|---|---|---|---|
| CMIN / HARV | 对矿区的上下文点击启动采矿；满载后回厂、卸货并继续往返 | 官方手册说明完整循环；R 有 Harvester=yes；点普通无矿地点不等价 | `harvest_at` 应触发原版采矿；勿以 MoveTo 到矿区即判已开始采矿 |
| CMIN / HARV 的 G | 用户报告可自动寻找矿区并采矿 | U / S2；CMIN 的限定实测见现场记录，HARV、搜矿范围与选择规则未测 | `guard` 必须验证此行为，再评估是否替代当前 auto_harvest；不能先承诺“最近矿区” |
| HARV 的攻击能力 | 有武器的矿车同时可能接敌 | R：Primary=20mmRapid；不证明采矿时完整选敌规则 | 采矿与受攻击不应被运行时一律判卡住或命令失败 |
| FV + Engineer | 乘员令 IFV 变为维修车辆；维修武器是负伤害 | M-RA2 p29；R：FV Weapon2=RepairBullet、RepairTurretWeapon=1，Engineer IFVMode=1，RepairBullet Damage=-50/Warhead=Mechanical | 不能用 FV 静态 Primary=HoverMissile 推断当前作用；需回读实际模式/乘员 |
| 维修 FV 的 G | 用户报告警戒时自动维修附近单位 | U / R / S2；Engineer-FV 的限定实测见现场记录，扫描范围、盟友与其他目标仍待测 | 普通敌人筛选条件不能用于此基础 guard；验证机械目标适用范围，不承诺修任意单位 |
| Engineer 点击建筑 | 按目标归属/状态可占领、修理或修桥；通常消耗自身 | M-RA2；pyra2yr 有工程师修理真机用例；本项目 CAPTURE 尚未完整实测 | 分别声明 `capture`、`repair_with_engineer`、`repair_bridge`，共用准确上下文适配 |
| Spy 点击对象 | 对单位进行伪装、进入目标建筑渗透等有不同操作 | 手册/规则给出用途，当前没有受控覆盖 | 伪装和渗透效果单独回读；不能套用敌方建筑掉血判据 |
| E1 / GGI / DESO / YURI 类 D | 同一部署键触发武器姿态或区域能力 | M-YR；R 可见不同部署配置 | 分类型给生效谓词，不把所有部署当 MCV 变身 |
| SMIN / YAREFN | 可在移动/建筑状态间转换，Slave 系统参与经济 | M-YR/R；不是简单 Harvester=yes 分类 | 经济能力不能仅靠 CMIN/HARV 名单或 Harvester 标志判断；具体行为单独验证 |
| 攻击特殊武器 | 控制、抹除、磁力、爆破等通过目标攻击产生不同结果 | M-YR/R；原版具体限制仍需核验 | 基础攻击验证目标/武器动作；组合任务按对应效果判断，不能统一要求目标掉血 |
| 已部署、被装载、停电依赖、弹药不足 | 同一命令可能不可执行或触发恢复流程 | 类型/规则支持条件存在，当前动态回读不足 | 反馈具体暂不可用原因，禁止自动把 limbo 消失计成死亡 |

R 的负伤害确实支持用户对维修武器的判断；它不能单独证明 G 的完整执行语义。`Mechanical.Verses` 也不能单独替代目标合法性、盟友关系和运行时扫描规则。

## 5. 对当前上层设计的具体影响

| 当前实现 | 玩家语义差距 | 建议 |
|---|---|---|
| `hold_position`、Hold、stance=hold 都翻译为 STOP | 名称不能保证永久不动/原版 G 警戒；stance=hold 的 MoveTo 不会先走到给定目标格 | 原样保留现状记录；新增基础 stop/guard 后再决定迁移旧名与卡片描述 |
| `guard_area` 在 Python 中逐拍选择最近可见敌人 | 额外策略；不能覆盖矿车/维修 IFV 原生警戒；无原版指定保护锚点 | 作为组合技法保留，与基础 guard 系列区分 |
| `advance_to_cell` 默认 aggressive + spread=1 | 自动攻击移动并展开队形，多于普通玩家 Move 的含义 | 基础 move 忠实请求，队形/覆盖推进作为组合技法 |
| `hold_and_fire` 主动选敌发 Attack | Attack 可能产生追击，名称不能保证严格保持位置 | 验证实际行为；不能将其当原版 Stop/Guard 的定义 |
| `harvest` 用 MoveTo 最近矿格 | 到位可在近邻格结算，无法证明 Harvest；自动重发还可能干扰引擎 AI | 首先测原版矿区点击/G，补基本采矿能力后再调整自动经济 |
| `cancel` 只结束运行时任务并释放单位 | 不发送停止命令；单位可能继续已接受的动作或原生巡逻 | 模型明确区分取消 Agent 任务与停止单位；停止必须经基础技法，联动策略另行设计 |
| 运行时多对象 DONE 模式 | 对象消失、移动到位不是所有玩家操作的统一终点 | 增加命令特定的生效/阶段结果，支持装载、消耗和变身 |
| 自动层每拍可能下新令 | 一次性玩家操作受理后仍可能被其他技法覆盖 | 临时租约与交还政策需明确；长期任务/自动经济的替换、优先级与禁止抢令需设计 |
| `tactics` 按静态条件筛卡片 | 武器模式、乘员、弹药、运动域不足会误报能力 | 类型知识 + 当前动态状态 + 目标适用查询；混合单位允许部分成功 |

基础操作技法可以在命令已生效后结束、释放租约；游戏的原生行为仍继续。长期任务可持续占用或持有目标约束，但需声明结束方式。不能为所有基础技法默认持久重发，也不能强制所有操作必须等到目标死亡/抵达才算命令成功。

## 6. 推荐的能力契约

不立即规定最终 Python schema，但下列语义应在实现前确定：操作名称（玩家语义）、执行单位、目标类别（地点/单位/建筑/矿格/路径）、必要玩家修饰（强制开火/强制移动）、局次与请求身份、每单位适用性/拒绝原因、依据帧与执行帧、命令生效回读、取消/替换规则。路径操作另带节点动作、循环和计划提交状态；append 只对已验证的能力开放。

底层可参考 `MouseOverCell`/`MouseOverObject` 和 `ObjectClickedAction`/`CellClickedAction` 来还原“单位对目标的上下文动作”，也可使用经核验的原版网络事件。两者都需要在游戏线程重查对象和可见性，核验未知参数及 UI/按键依赖。不得把 Enum 有名字、Mission 编号存在或裸内存写入成功认作玩家操作支持。

部署、采矿、护送等不应由 L0 选择战略目标。点哪个目标由模型或技法决定；原版自主警戒/采矿内部选择属于玩家指令本身的既有行为，不是 L0 新增策略。这与现有“L0 从不选择”原则相容。
