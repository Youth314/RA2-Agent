## 实现与边界

EscortUnit / escort_unit 与 GuardStructure / guard_structure 共用 GUARD_OBJECT=17；前者只接受另一个己方车辆，后者只接受己方建筑，actor 均限定单个己方车辆。GameState.object_guard_interface_version=21 独立声明 v1；旧 DLL 缺失按 0 / unsupported，MATCH 隐藏两个卡片，明确拒绝记忆调用。既有 Guard / Stop / Attack / Target 字段和编号保持兼容。

复用 UnitOrder 的 target_object=3、expected_target_native_id=8、expected_target_house=9、expected_target_type=10 与 actor 信封 5–7。己方目标使用 Object.native_id=21，不借仅合法敌方才导出的 order_target_native_id。发送前重读之前固定 actor / target 的 pointer、native ID、house、具体类型及 type_pointer，要求跟踪身份属于当帧；重读后任一绑定改变或超过 150 帧即拒绝，不追随变身保持的 Agent ID，不从历史身份缓存补齐缺失字段。同身份普通移动允许。

L0 拒绝 actor / target 缺席、非己方、死亡、limbo、离图、车辆变身、错误目标类别、自身目标及无效地图位置；allow_foreign 不放宽。DLL 从 TechnoClass::Array 按地址值找成员后才读取字段，以固定 WhatAmI ABI、UniqueID、Owner、IsAlive / IsOnMap / Health、变身及实际地图边界复查。成功只调用 ClickMission(actor, Mission::Area_Guard, object_target, nullptr, nullptr)，检查返回值，不走旧对象坐标缓存、不写 Target、不开放任意 Mission。

回读只匹配依据帧后观察到的新 MegaMission(type=4)：当前玩家、actor / target 的 RTTI=52 与原版 ID、Mission_Area_Guard=11、空 destination / follow、非 planning，且完整绑定和当前合法性保持。建筑具体类型为 6，但事件对象引用仍为 RTTI=52。基线输入的 out / do 转移及重新排期均不算新输入；旧 Mission、目的地、另一对象或事件自身未来 frame / is_executed 均不单独证明效果。回执为 observed_match / native_input_observed，observations 保留输入观察帧、事件帧和目标类别。

两个薄技法经正常 Commander.call 受理及 Squad 执行，以 operation_observed 结束单次操作、释放 actor 租约；目标不进入 actor 集合或租约。unknown / unverified 保留原计划回读，不重发；cancel 只结束 Agent 管理，不发 Stop。原生命令在租约释放后可能继续。没有专用持续护送关系回读，不要求实际攻击 Target 指向护送对象，不宣称已跟随、到达、永久驻守、维修或作战保护。首轮真机效果拟限定 MTNK，其他车辆、盟友及其他类别保留未验 / unsupported。
