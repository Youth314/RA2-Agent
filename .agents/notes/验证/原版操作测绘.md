# 原版操作测绘

日期：2026-10-02。范围：S2 的 T01–T04 玩家操作对照；首轮限定场景已完成，实际结果与限制在[玩家操作能力表](../引擎/玩家操作能力表.md)单源维护。S3 接口实现不在本轮范围内。

## 接入与证据

使用 config/match.json 的 Alpha / Beta 名册启动联合对局，Alpha 采集 T01 / T02 / CMIN / FV，Beta 仅短暂只读采集；HARV 对照按用户决定取消。临时只读脚本 .agents/tmp/s2-player-mapping/observe.py 默认连接 Alpha 的 14521 端口，写入 observations.jsonl；参数 14522 连接 Beta，写入 observations-14522.jsonl；不创建 GameSession，不启动自动技法，不发送单位命令或修改引擎配置。用户执行原版按键与点击，模型需要发送游戏动作时仍只调用技法；人工对照不等于开放原始命令工具。

脚本每约 0.1 秒读取 GetGameState，记录 frame、stage、player_index、money、己方对象的 pointer、array_index、类型、位置、health、selected、mission、destination、limbo 与部署状态。从 GameState.raw 的字段 11 / 12 / 13 解析 out_list / do_list / megamission_list，保留原始事件字节及 MegaMission 的 whom、mission、target、destination、follow、planning。事件目标是 TargetClass 的 m_RTTI 与 m_ID 编码，不是 Agent ID、对象指针或已确认的 array_index；RTTI=52 的对象编码尚未与本项目身份表建立映射，不得直接替换使用。

解析字段依据固定版本 ra2yrproto 的 ra2yr.proto 与 ra2yrcpp 的 state_parser.cpp，版本定位见[玩家操作能力表](../引擎/玩家操作能力表.md)。事件可能在多个快照重复出现，应按事件身份与观察帧整理，不能以重复快照数量统计下令次数；缺少事件不能据此确认没有下令。固定版本 EventParser 在复用消息槽且列表长度不变时没有清除旧 oneof；现场观察到 FrameInfo 事件残留上一条 MegaMission 载荷。解析须按 event_type 分派，只接受 4 / 5 对应的 MegaMission / MegaMission_F 载荷，不能仅凭字段存在判断事件类型。已采原始日志保留，分析时过滤残留字段；Alpha 原始日志由过滤前脚本采集，分析已按 event_type 排除残留载荷；Beta 采集及后续脚本均启用过滤。现有对象状态没有 Target / Follow、乘员、IFV 模式与货量；事件中的目标意图不能替代持续对象状态。

测试标记记录准备与完成阶段的采样帧，标记帧不等于按键发生帧。实际事件帧、单位状态变化与用户操作说明共同确定观察窗口。单位进入后缺席不能直接判死亡，维修能力改变须由乘员准备说明与实际增血交叉确认。当前配置支持后台推进，持续暂停恢复仍未确认，S 不表示暂停游戏。

## 阵营确认

名册中的 participant.side 原样渲染为 spawn.ini 的 Side。当前 0 / 1 分别与 rulesmd.ini [Countries] 的 Americans / Alliance 相符；本轮读取 House.faction 确认为 Beta=Americans、Alpha=Alliance，两者均属盟军。不能直接把数值 0 / 1 当作盟军 / 苏军区分，准备类型专用场景前必须核对实际 House.faction 与现有单位。HARV 场景因阵营误判曾被提出，用户取消后未执行；未修改名册以切换阵营。

## 人工操作顺序

| 场景 | 准备与操作 | 记录与判据 | 扩展条件 |
|---|---|---|---|
| T01-S | 选一台 Grizzly Battle Tank，移动途中按 S，保留选中状态 | 玩家事件、移动中断、后续 Mission 与目的地 | 同样对 GI 执行；停止不表示永久禁止自动攻击 |
| T01-G | 对同一静止战斗单位按 G，短暂等待 | 玩家事件与后续任务；比较 S / G 是否不同 | 安排敌人进入再退出范围，才判断追击和回锚 |
| T02 位置 | 对选中坦克 Ctrl+Alt 点击附近空地 | 地点编码、抵达与后续警戒 | 未抵达前的接敌需另设场景 |
| T02 护送 | A 坦克 Ctrl+Alt 点击 B 坦克；再单独选 B 移动，保持 A 不收新令 | follow / target / destination、双方轨迹及跟随 | 目标消失、临时不可用与盟友对象按需要补测 |
| T02 建筑 | 展开 MCV；选坦克 Ctrl+Alt 点击己方建筑 | 建筑目标编码与后续行为 | 没有敌人时只确认命令与驻守状态 |
| T03 CMIN / HARV | 建成对应矿厂与矿车；矿外 S 后按 G，再与普通移动 / 点矿对照 | 搜矿、HARVEST / RETURN / UNLOAD、位置和资金变化 | 无货量观测时不能量化载满；不凭一次采矿声称最近矿选择 |
| T04 FV | 空 FV 和 Engineer 进入后的 FV，附近有受伤己方载具 | G 与点名维修的事件、轨迹、对象增血 | 再对移动伤车护送，并卸出 Engineer 对照；不能以形状或任务编号替代增血 |

每次仅给一项操作，完成后先整理该窗口证据，再继续下一项。用户说明目视结果，Agent 记录事件和前后状态；无敌人或目标条件不足时缩小结论，不补造成功场景。准备矿车、Engineer、FV 和受伤载具可由用户完成，不要求自动化重建开局。

出现退出对局、读取错误或无法辨别对象时停止该场景并保留证据。收尾停止采集进程与本轮实例，将两份 spawn.ini 从 .render-bak 恢复并比较一致；原始日志保留在临时目录。未确认项目保持未执行或无法确认，不因方法文档存在而标记通过。

## 独立离线验证

入口：PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 .agents/tmp/s2-player-mapping/verify_recording.py。结果为 11 项通过，原始输入包含 13291 个 Alpha snapshot；报告保存在同目录 offline-verification.json，包含采集脚本与录制日志的 SHA-256。使用 AST 仅加载 observe.py 的四个纯解码函数，不执行连接或采集线程；真实 Event 字节重新包装进测试消息，完整 GameState 测试信封与错误 oneof / 负值用例为合成输入，不声称是完整原始游戏帧。

覆盖真实事件字节回读、非 MegaMission 类型的残留 oneof 过滤、两种 MegaMission 的类型匹配、RTTI=0 但 id 非零、带符号字段、GameState.raw 保留未知事件字段，以及已采 Guard 目标、CMIN 输入与周期、Engineer 装卸后的维修对照、移动中增血和修满后远处再受伤不恢复跟随。事件去重仅用于按原始字节选取解析用例；同一操作的 out / do 表示可能不同，不据此统计逻辑命令数。

组件入口：PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m unittest tests.test_proto tests.test_state，64 项通过。两组测试均未启动游戏、修改业务代码或运行全量回归；结果验证当前解析逻辑和已采证据一致性，不增加新的原版行为或 DLL 下令等价性结论。实际效果与未测边界继续由能力表维护。
