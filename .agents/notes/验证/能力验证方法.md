# 能力验证方法

更新日期：2026-10-03。状态：用户已确认按功能组开发、集中真机验证及最小检查约定；依据原版资料、源码静态审计和既有实测记录修订。本文规定调查与验证的方法，不表示待测能力已通过，也不要求建设新的测试平台。

## 1. 验证目标与投入

以当前需要回答的问题选择最小充分验证。逻辑约束需覆盖有效输入、关键拒绝和结果未知；原版操作需观察实际效果；宿主集成需验证真实生命周期。无需每次执行全部层次，不以自动化比例、测试数量或无头运行为目标。

优先复用既有 unittest、短脚本、固定录制和真实游戏场景。单次实验可以通过人类操作与画面观察完成；场景准备明显比实验更耗时、或操作与观察由用户完成更快时，应邀请用户协助。只有重复成本高、失败影响大或确有回归需求时才增加自动化，不为单次问题设计通用调度、场景 DSL、复杂矩阵或独立测试服务。

相关契约、实现、回读判据和使用方按功能组合并推进，稳定后集中构建、部署和真机验证；不因每增加一个字段或补丁就单独起局。每项检查先说明其要回答的问题；通过后停止，只有新改动、失败或未解决问题才扩大或重跑。同组动作在已确认范围内连续执行，复用同一局、对象与采集连接，批次结束统一保存最少证据和回滚。

| 改动 | 默认检查 | 复用与停止条件 |
|---|---|---|
| 协议解析、原生身份或合法信息边界 | 改动对应的编码、兼容或关键拒绝用例 | 未改的解析、原生策略和身份测试不重复运行；不同层的有效边界用例保留 |
| 执行器、意图或技法行为 | 新行为和受影响分支；功能组结束时一次相关回归 | 按方法或测试类选择，不默认把整个 state/identity/proto/Stop/Guard 集合列为固定前置 |
| 文档、临时只读采集与分析脚本 | 文档差异检查；脚本语法或一次实际运行，按需核对输出 | 不默认补一套序列化、生命周期或部署测试；写入环境的部署/收尾复用已验工具 |
| 真机原版行为与接口对照 | 功能组准备完成后，一轮覆盖必要新路径、关键效果和真实身份变化 | 本局就绪只作运行前置；不重复已验加载/空目标/Stop 正例，不另起一局补相同观察 |

未测型号、灰雾/隐形/伪装、死亡、指针复用等边界继续标未验，只有当前支持声明或实现变更依赖它们时才纳入本批。数量本身不是删除用例的依据；等价重复、只复述实现或不回答当前问题的检查应合并或移出执行计划。配置、部署和对局动作授权仍按具体批次取得，测试减量不扩大支持声明或取消用户的环境约束。

## 2. 从玩家语义定义能力

先描述玩家如何操作、期望建立什么行为、哪些单位和状态会改变效果，再找对应实现。相同按键可以启动不同原生行为；单位类型、乘员、武器模式、运动域和目标类别均可能影响适用性。

Mission 编号、函数名、协议字段和成功返回是实现线索，不能单独证明玩家等价效果。允许游戏执行原生寻路、接敌、采矿往返或维修；若运行时模拟这些行为，明确记录其实现差异，不能承诺原版等价。

能力范围与单位差异维护在[玩家操作能力表](../引擎/玩家操作能力表.md)，接口候选及复用边界维护在[接口复用评估](../引擎/引擎接口复用评估.md)。

## 3. 分开证据与结论

| 证据 | 能证明什么 | 主要限制 |
|---|---|---|
| 官方手册/原版规则 | 玩家入口、声明语义、配置与数值 | 不证明当前 DLL 接口可执行 |
| 固定版本源码 | 类型、事件布局、调用和校验路径 | 不证明运行 DLL 与行为一致 |
| 离线替身或回放 | 给定状态下的编码、意图、约束与结算 | 不证明新原版命令生效、真实寻路或游戏因果 |
| 人工或脚本真机对照 | 指定版本、配置和场景下的实际效果 | 不自动推广到所有单位、联机或其他配置 |
| DSH 集成观察 | 指定接入模式下的工具隔离、持久化、恢复与唤醒 | 不替代底层原版操作验证 |
| 游玩经验/推测 | 有价值的待验证问题和场景 | 需要标明来源，不能写作已测能力 |

结论标记为通过、失败、未执行或无法确认，并附适用范围。状态观察匹配与本次命令因果确认分开；目的地或 Mission 下令前已成立时，不据此断言新请求生效。

## 4. 优先检查的边界

受理、提交、观察到操作状态与任务完成分别记录。cancel 结束 Agent 任务，不默认等于 Stop；原版命令可能继续。Timeout、暂停或传输中断后结果可能未知，先回读再决定是否重试，部署切换、装卸、生产或追加计划不能盲重发。

每次下令前重查局次、归属、身份、可见性、动态能力和租约。混合单位部分成功需逐单位说明；变身、装载、消耗和缺席不统一视为死亡。原生持续行为不应被默认逐拍重发打断。

执行场景先确认宿主方式、L1 进程是否存活和游戏帧是否推进。watcher 只侦测和唤醒，不接续 L1 任务；MCP 生命周期、暂停与冷玩家恢复的当前限制见[DSH 测试接入审计](DSH测试接入审计.md)。具体待改契约见[接口审计草案](../../drafts/接口/L1基础接口契约与现状审计.md)。

### 服务端拒绝的受控故障注入

本地校验拒绝不能证明 DLL 的二次校验有效。需要补该证据时，可以在隔离测试 client 适配器中对经过正常技法受理、作用域/租约与 L0 校验的请求注入固定故障；不修改生产 Validator，不开放任意 Mission 或模型原始下令。每次验证一个拒绝条件，保留正常请求、实际故障载荷、真实回复和任务结算，再用合法请求确认正常路径仍可用。非零回复可能附带请求回声，先检查结果码，再决定是否解析结果。

对照对象必须按真实阵营与身份定位；同一错误原文可能覆盖多个约束，避免同时改变无关条件。非己方对象拒绝可由技术采集层准备跨实例身份对照，不传入模型合法观测或正式目标选择；完整状态中的“第一个非己方对象”可能属于中立阵营，不能代替指定对手。动态场景须明确采样窗口，短窗口无新事件或对象变化不能扩展为无限期无副作用。已执行的范围与局限见[Guard 拒绝验证](Guard接口验证.md#服务端拒绝边界限定场景通过)。

## 5. 选择验证方式

| 当前问题 | 优先采用 | 何时扩大范围 |
|---|---|---|
| 参数、编码、归属或租约是否正确 | 既有离线测试或最小状态序列 | 真实事件/运行时路径影响结果时 |
| 原版 G、保护、采矿或维修实际做什么 | 玩家操作 + 状态记录 + 画面对照 | 需要确认接口等价或单位差异时 |
| 技法是否正确选目标、何时结束 | 固定观测回放或短真机任务 | 依赖实时接敌、寻路与恢复时 |
| MCP 分派或协议是否正确 | FakeSession 或独立 stdio 驱动 | 涉及 DSH 实际插件加载和作用域时 |
| 模型 idle 后任务/唤醒是否继续 | 指定 DSH 接入方式的真实集成场景 | 冷恢复、重启或联机确属目标范围时 |

表中是可选验证方式，不是必须逐级通过的流水线。源码已经能够排除的未实现分支不必用真机重复撞失败；原版效果不能仅靠替身通过替代。路径、版本和现成入口见[DSH 测试接入审计](DSH测试接入审计.md)，实际操作见[真机测试手册](真机测试手册.md)。

## 6. 最小实验与人工协作

一轮实验可以连续验证多个相关问题，逐项明确初始状态、操作、成功/失败观察点和结束条件。每项未知操作单次提交，不并发抢写、不盲重发；比较人类操作与接口操作时尽量保持同一版本、单位状态与场景。初始准备可由用户手动完成，不要求脚本复现整套开局。

同一游戏实例使用一个命令执行者。自动层在实验中停用或明确纳入，避免隐式改令；并行 agent 可查源码、准备说明或分析记录，不同时抢焦点和指挥单位。多连接不等于允许多写入者；联机双实例是一个联合实验。

人工协作请求使用简短格式：目的、需要准备的单位/状态、具体按键或点击、需要观察的变化、结束/停止条件。说明 Agent 同时记录哪些帧和字段；如果目视或用户口述已足够回答问题，不强制录屏或完整日志。缺少证据时明确无法确认，不要求用户操作危险的越界/越权命令。 同时说明等待期间的独立工作及其边界；没有工作时明确仅等待，不因等待超时推定用户已经操作或授权。

优先人工协助的例子：准备受伤载具与 Engineer 进入 FV 的场景；依次执行 G 与 Ctrl+Alt 护送，观察是否自动维修、跟随和返回。该例是待执行方案，原生行为的结果仍以能力表对应实验记录为准。

## 7. 留证、更新与停止

最低留证包括问题、相关版本/配置、单位和操作、前后状态或画面观察、结论及限制。涉及宿主再加 preset/player 身份与生命周期，涉及联机再加两侧观察。完整录制、包追踪或额外探针只在这些最小证据不能解释结果时启用。

临时脚本和实验产物放 .agents/tmp/ 下按问题组织；稳定结论写 notes，候选方案与缺陷留 drafts。先更新能力表/测绘结果/接入审计中的唯一事实源，再修改计划或链接；不复制多份相同状态，不把修复建议写成已实现。

每批使用一个验证事实源，记录范围、结果、证据入口和限制；计划与交接链接到该记录，不复制采样细节、哈希或长执行历史。持久部署备份与清单继续保留，普通检查不再另建多层准备、审阅与复核报告。

已经有充分证据回答问题时结束实验；重复失败时先隔离条件，不无目的重跑。出现崩溃、无帧推进或未知排队命令时按真机手册留证和处置，不把恢复后的旧命令误归因于新的测试。
