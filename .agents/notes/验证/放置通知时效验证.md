# 放置通知时效验证

日期：2026-10-03。状态：实现提交 bf8dcd0，关联建筑的待发通知过期处理及 15 项相关离线检查通过。未启动游戏、部署 DLL、改配置、重启现存 MCP / DSH 或向真实 DSH 投递消息。事件就绪判据复用[待放置判据验证](待放置判据验证.md)，本页只维护通知积压与送达前的时效范围。

## 问题与契约

旧 WakeBridge 队列只保留 frame / text，在后续 request 的合并载荷中按 stale_frames 清理，没有关联对象或当前就绪状态；静默帧不清理队列。建筑已经放置、但通知仍在时间期限内时，后续告警可能连同旧“完工待放置”说明一起送达。独立 DSH 报告没有完整生产阶段原始帧，不能据此逐次归因原报告中的四次通知，背景见[Attack 报告复核](Attack玩家接口验证.md#独立-dsh-建筑批次与报告复核)。

Observer 的 EventLog 使用同一 IdentityTable，placement_ready 只为己方真实就绪建筑附带 Agent ID / 显示名；所有关联 ID 已知时才生成 buildings 数据，不输出 pointer 或 native_id。report_trouble 与 watch 共用 wake_messages，将普通告警和每个关联建筑的放置说明分别保留；同批通过 WakeBridge.request_many 合并为至多一次 HTTP 投递，成功仅消耗一次额度，不因拆分而追加唤醒。

Wake 新增可选 placement_building，表示己方建筑 Agent ID。该字段不授予游戏操作权限，不传给引擎；旧序列化载荷缺字段时默认 None，普通及无关联的旧放置通知仍按时间期限处理。同批记录各自保留关联和投递结果，外部 HTTP 信封仍为 text / frame / tactic / session / merged。

MicroLayer.tick、Autopilot.run、Commander.status 与 watch 使用已有 Observation / IdentityTable 调用 WakeBridge.update。当前 ready_building_factories 能完整映射时，带关联 ID 的待发通知若不再属于该集合即标记 expired，并从待发队列移除；包括已落地、对象消失、身份改变或不再满足就绪条件。另一个建筑仍待放置不会保留旧建筑通知。缺少 state / identity 或就绪对象映射不完整时，不推断建筑状态，保留原 stale_frames 时间上限。

清理不读取额外引擎状态、不提交游戏命令、不自动 HTTP 重试、不重置限流时钟或额度。普通损失、渗透等告警独立保留。后续新 request 仍依原限流与额度合并有效待发说明；投递失败及 HTTP 200 / ok:false 继续保留内容。过期不擦除原始游戏事件，内存原请求标记 expired，并追加 wake_expired 决策日志；status 不再将过期说明列为“唤醒未送达”。

## 限制与后续
