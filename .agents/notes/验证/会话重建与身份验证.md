# 会话重建与身份验证

日期：2026-10-03。状态：实现提交 c85f1b6，相关离线检查通过，未部署或重启现存 MCP、未新增真机批次。范围为同一 GameSession 实例在连接中断、reset 或已检测的局次边界后重建；不改 DLL、协议、配置、技法、执行器与重发逻辑。

## 问题与契约

源码核查发现每次 GameSession._connect 新建 Observer / IdentityTable，ID 从 1 重新分配；旧上下文的 call 可以在 ensure 重建后直接受理，旧数字可能指向新对象。旧任务会丢弃，但原提示仅写到 stderr，玩家工具输出没有会话重建提示。此路径可解释一种风险，不据此认定既有真机报告中 ID 变化的具体原因。

IdentityTable 增加正整数 start_id 和只读 next_id。GameSession 在 reset 或 _discard_match 清除 Observer 前保存分配起点，重建的空表从该起点分配；包括已经消失的 ID 均不复用，不保留旧对象绑定。Observer 显式按 identity is not None 接收注入表，避免空表因 __len__ 为 0 被替换。原有同表变身与原生身份检查不改动。

每次成功连接递增会话上下文编号；status / tactics 显示当前编号。首次连接提示使用本次 status 的 ID，重建后提示旧 ID 与任务失效、已提交的原生命令未撤销、结果可能未知且勿盲重发。只有当前上下文的 status 成功渲染返回后，call / cancel 才能进入 Commander；tactics 不解除限制。首次连接也执行该门控。未读当前 status 的请求明确未受理，不保存或自动补交。ensure 与实际分派之间检测到边界时拒绝请求，避免访问已丢弃的 Commander。

reset / 重建继续丢弃原有任务、租约和待回读计划，不迁移或重发旧未知结果，不发 Stop。原生命令可能仍由游戏执行，任务丢弃不代表原生命令取消。后台自动层沿用既有活动对局/帧推进门控，当前 status 门控仅约束玩家 call / cancel，不承诺暂停全部 automatic 技法。

两个身份检查覆盖消失后的 ID 仍不复用及非法起点拒绝。六个重建检查使用实际 GameSession._connect、Observer、IdentityTable、MicroLayer 与 Commander，只替换传输和线程：首次 call 拒绝与 tactics 不解锁；有任务时断连、关闭旧连接、清空任务、重读提示、旧 ID 拒绝且新 ID 受理；_discard_match 在清除 Observer 前保存起点；reset 后 cancel 需重新读状态；status 渲染失败不解锁；ensure 后分派前的边界明确拒绝。其余 13 项仅回归受影响的帧边界、会话参数与卡片帧号，不运行完整 MCP / 身份 / Attack 套件或原生编译。
