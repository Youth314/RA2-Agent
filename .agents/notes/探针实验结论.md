# 探针实验结论

验证 ra2yrcpp 能否作为本项目的引擎接口。环境见[平台与引擎选型](平台与引擎选型.md)。

## 结论

| 能力 | 结果 |
|---|---|
| 在进程启动时加载 DLL | 可用 |
| 读取游戏状态 | 可用，逐帧完整 `GameState` |
| 区分迷雾 | 可用，`Cell.shrouded` 即精确可见性 |
| 下发命令 | 可用。自写客户端；`SELECT`、`STOP`、`MOVE` 均已实测生效 |

官方 CLI 的命令接口不可用（见"上游缺陷"），命令通道由自写客户端实现，见"命令通道"。

## 可用的启动方法

1. 用 `patch_gamemd.py --auto-patch` 把 DLL 加载器打进 `gamemd-spawn.exe`，产物 `gamemd-spawn-ra2yrcpp.exe`。
2. 在游戏目录放置 `spawn.ini` 与 `spawnmap.ini`（解压后的地图文件）。
3. 运行 `gamemd-spawn-ra2yrcpp.exe -SPAWN`，游戏直接进入对局，不经主菜单。

`spawn.ini` 模板：

```ini

MultiEngineer=Yes

[HouseHandicaps]

[HouseCountries]
Multi2=1
[HouseColors]
Multi2=1
```

## 实测事实

### 加载时机

DLL 必须在进程启动时加载。服务由其 `ExeRun` hook（`0x7cd84d`）内的 `start_service()` 启动，该 hook 每次进程运行只触发一次，运行时注入为时已晚——DLL 会加载、hook 会安装，但服务永不监听。

### 崩溃成因

`-SPAWN` 缺少 `spawn.ini` 时退化为普通主菜单，此时开始遭遇战必崩：`EXCEPTION_ACCESS_VIOLATION`，`Eip=00000000`，即调用空函数指针。CnCNet 的网络回调只在客户端驱动下初始化，菜单路径下未经初始化。

该崩溃与 ra2yrcpp 无关：未 patch 的原版 `gamemd-spawn.exe` 崩溃时 `Eip`、`Esp`、`Ebp`、`Ecx`、`Edx` 逐字节一致。补上 `spawn.ini` 直接进对局后不再崩溃。

### patch 目标

必须 patch `gamemd-spawn.exe`。patch `gamemd.exe` 后进程启动即崩于 `0x804000`，去掉 `patch_gamemd.py` 中 spawner 独有的 `.p_text` 段信息后产物 md5 不变，故成因不在该处。

Steam 版 `gamemd.exe` 与 `gamemd-spawn.exe` 的游戏代码相同：`.text` 段的虚拟地址与大小一致（`VA=0x1000`，`VSize=0x003df38d`），`LoadLibraryA` 与 `GetProcAddress` 的 IAT 地址亦一致（`0x3e1220`、`0x3e1250`）。

### 迷雾

- `Cell.shrouded = ((AltFlags & 0x8) == 0)`，是**永久的"已探索"标志**。5,249 个发生状态变化的格子中，无一例从可见回到遮蔽。
- `Cell.visibility` 与 `Cell.shroud_state` 在 proto 中声明，但 `Cell::copy_to` 从不填充。
- `spawn.ini` 的 `FogOfWar=No` 令引擎只有未探索与可见两态；`Yes` 会引入灰色层。
- **因此 `FogOfWar` 必须为 `No`。** 此时 `shrouded` 即精确可见性，按它过滤 `objects` 得到诚实的观测。

### 观测规模

| 项 | 值 |
|---|---|
| 单帧未压缩 | 约 11 KB（最小 10,255，最大 347,558） |
| 地图格 | 10,230 |
| 对象数 | 213 – 242 |
| 数分钟一局 | 5,399 帧，约 60 MB 未压缩 |

录制每帧一条 `GameState`，gzip 压缩后以 varint 长度前缀串联。一局 20 分钟约 200 MB 未压缩，不能直接交给模型，必须有压缩层。

### 通信

服务监听 `TCP 0.0.0.0:14521`，WebSocket 承载 protobuf。命令流程为：发 `Command{CLIENT_COMMAND}`，收 `RunCommandAck{id, queue_id}`，再用 `POLL_BLOCKING` 取结果队列。

## 命令通道

WebSocket 承载 protobuf，无 TLS。每帧一个消息，同步请求-响应。

发送 `Command{ 1: command_type, 3: Any{ 1: type_url, 2: value } }`，`command_type` 取 `CLIENT_COMMAND`(2) 或 `POLL_BLOCKING`(5)。

握手为发一条 `GetSystemState`，响应体是 `RunCommandAck{ id, queue_id }`；之后以该 `queue_id` 走 `POLL_BLOCKING` 取结果。结果可能分多批到达，必须循环轮询。

实测生效的命令：

| 命令与动作 | 观测到的效果 |
|---|---|
| `UnitOrder` + `UNIT_ACTION_SELECT`(2) | 对象的 `selected` 变为真 |
| `UnitOrder` + `UNIT_ACTION_STOP`(10) | 对象的 `mission` 由 `Mission_Guard`(5) 变为 `Mission_Stop`(13) |
| `UnitOrder` + `UNIT_ACTION_MOVE`(6) | 对象的 `mission` 变为 `Mission_Move`(2) |

`coordinates` 是**世界坐标**（lepton），服务端经 `CellClass::Coord2Cell` 转格。**越界坐标会崩溃游戏**：`TryGetCellAt` 对地图外的格返回非空但无效的指针，`ClickMission` 调用时跳到地址 0，产生 `EXCEPTION_ACCESS_VIOLATION`（`Eip=0`）。下令前必须自行校验目标格在地图范围内。

## 运行约束

**单机模式失焦即暂停。** hook 挂在游戏主循环上，窗口不在前台时主循环不推进：命令排队不执行，帧号不增长。Agent 运行时若需要游戏持续推进，必须保证窗口保持前台，或找到关闭该行为的方法。

## ra2yrcpp 上游缺陷

| 缺陷 | 位置 | 影响 |
|---|---|---|
| `AutoPollClient::start()` 从未被调用 | `src/multi_client.cpp` | CLI 命令接口不可用，恒抛 `map::at` |
| `record` 子命令读 `-i`，参数名却是 `input-file` | `src/ra2yrcppcli/main.cpp` | 录制导出不可用 |
| `Cell.visibility` / `shroud_state` 从不填充 | `src/ra2/state_parser.cpp` | 无三态迷雾 |
| patch `gamemd.exe` 崩溃 | `scripts/patch_gamemd.py` | 只能 patch spawner |
