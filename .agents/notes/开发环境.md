# 开发环境

## 运行位置

工具与适配层**全部在 WSL 内运行**，不在 Windows 侧。

WSL 为镜像网络模式（`C:\Users\Youthz\.wslconfig` 的 `networkingMode=mirrored`），故 WSL 可直接连到 Windows 上只监听 `127.0.0.1` 的服务。实测服务端绑在 Windows 的 `127.0.0.1:14521`，WSL 用 `ws://127.0.0.1:14521` 直连成功。

因此不必把脚本复制到 Windows，也不必用 Windows 的 Python。

## Python

WSL 侧为 Python 3.14，**只用标准库**：protobuf 与 WebSocket 均手写，不需要 `protoc`、`google.protobuf` 或 `websocket-client`；测试用标准库 `unittest`。项目至今未安装任何第三方包。

```sh
cd ~/ra2-agent
PYTHONPATH=src python3 -m unittest discover -s tests -t .
```

`PYTHONPATH=src` 是必需的（尚未 `pip install`）。`tools/` 下的脚本多数还引用旧的 `ra2client`，需 `PYTHONPATH=src:tools`。

## 启动与关闭

从 WSL 启动。必须用 PowerShell 与绝对路径：`cmd /c start` 配相对路径会静默失败且不报错。

```sh
/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -NoProfile -Command \
  "Start-Process -FilePath 'D:\Games\ra2probe\gamemd-spawn-ra2yrcpp.exe' -ArgumentList '-SPAWN' -WorkingDirectory 'D:\Games\ra2probe'"
```

约 25 秒后 `127.0.0.1:14521` 开始监听。关闭用 `taskkill /F /PID <pid>`。

## 焦点

RA2 单机在窗口失焦时暂停主循环：排队命令不执行，帧号不增长。**同步命令不受影响**，故纯观测无需焦点，只有下发命令需要。

`tools/winfocus.py` 经 `SetForegroundWindow` 把游戏置前；`tools/batchkit.py` 的 `focused_batch` 保存当前前台窗口、交给游戏、结束时归还，并发 `tools/notify.py` 的系统通知。长批次据此可无人守候。

**恢复主循环需要真正的焦点切换，光是「已经在前台」不够。** 实测：游戏被暂停后，`focus_game()` 返回成功且 `GetForegroundWindow` 报的正是游戏窗口，但帧仍不增长；先 `winfocus.py away` 再 `game` 造出一次焦点切换，帧立刻恢复到约 60 fps。故脚本内自行置前不可靠，长驻脚本跑批前应先 `away` 再 `game`。

暂停中的排队命令不会丢：恢复后照常执行，此时可能已脱离下令时的语境。`MicroLayer.run()` 按帧节流，暂停时不下令；直接调 `tick()` 则无此保护。

## 诊断

```sh
# 游戏是否在跑
/mnt/c/Windows/System32/tasklist.exe | tr -d '\r' | grep -i gamemd
# 服务是否在监听
timeout 3 bash -c "echo > /dev/tcp/127.0.0.1/14521"
# 帧是否推进（最可靠的健康判据）
#   python3 -c "..." 见 tools/ra2client.py 的 is_advancing
```

崩溃报告在 `D:\Games\ra2probe\EXCEPT_CNCNET.TXT`，服务日志在 `D:\Games\ra2probe\ra2yrcpp.log`。
