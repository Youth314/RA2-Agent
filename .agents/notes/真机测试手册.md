# 真机测试手册

在真机上跑测试的操作流程。环境事实（路径、网络、Python）见[开发环境](开发环境.md)；引擎行为与实测结论见[探针实验结论](探针实验结论.md)、[命令能力测绘结果](命令能力测绘结果.md)；代码接口见[技法框架](技法框架.md)与 `src/ra2agent/` 各模块文档。

只看一页的话，记住三件事：**失焦即暂停**、**恢复焦点必须 `winfocus.py reset`**、**每次只验一条新命令**。

## 二、启动游戏

必须用 PowerShell 与绝对路径，`cmd /c start` 从 WSL 启动会静默失败。

```sh
/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -NoProfile -Command \
  "Start-Process -FilePath 'D:\Games\ra2probe\gamemd-spawn-ra2yrcpp.exe' -ArgumentList '-SPAWN' -WorkingDirectory 'D:\Games\ra2probe'"
```

**约 3 秒后端口就监听，但此时还没进对局**，要等到 `stage=2` 且恰好一个 `current_player`：

```python
import time
from ra2agent.client import Client
from ra2agent.constants import LoadStage

client = Client(); client.connect()
for _ in range(40):
    state = client.get_state()
    mine = [h for h in state.houses if h.current_player]
    if state.stage == LoadStage.INGAME and mine:
        print("进对局：帧", state.frame, "阵营", mine[0].name); break
    time.sleep(3)
```

## 三、焦点：最容易踩的坑

- 游戏失焦即暂停主循环：排队命令不执行，帧号不涨；同步命令（读状态）不受影响。
- **恢复主循环需要一次真正的焦点切换。** 已经在前台时再置前不会产生切换，游戏不醒——这是最容易误判成「崩溃」的地方。
- 正确做法是一条命令：

```sh
python3 tools/winfocus.py reset      # 先移开再置前
```

- **跑批期间不要动键盘鼠标。** 你切窗口、打字都会把焦点抢走，游戏随即暂停，脚本会报「帧不推进」。要长时间无人跑批用 `tools/batchkit.py` 的 `focused_batch`，它占住焦点、结束时归还并发系统通知。
- 脚本内不要自己调 `focus_game()`：对已经在前台的窗口无效。跑批前由外层命令 `reset`。

## 四、判定「暂停」还是「崩溃」

| 现象 | 含义 | 处置 |
|---|---|---|
| `GetGameState` 正常、帧号不变 | 暂停（失焦） | `winfocus.py reset` |
| `GetGameState` 超时、端口关闭、进程消失 | 崩溃 | 见第七节留证 |

命令下发后帧不推进时，执行器报的是 `GameNotResponding`（命令是否生效未知），不是命令失败——**暂停期间排队的命令不会丢，恢复后照常执行**，那时已脱离下令时的语境。

## 五、跑一次测试

把重置焦点与脚本放在同一条命令里，中间不要插入别的操作：

```sh
cd ~/ra2-agent
python3 tools/winfocus.py reset
PYTHONPATH=src:tools python3 .agents/tmp/你的脚本.py
```

脚本骨架：连接 → 取底图与类型表 → 读一帧 → 做事 → 判帧推进。临时脚本放 `.agents/tmp/`（不入库，可随时删）。

```python
from ra2agent.client import Client
from ra2agent.observation import Observer

client = Client(); client.connect()
observer = Observer(client).bootstrap()          # 地图与类型表各取一次
state = observer.poll()
print(state.summary())

before = client.frame(); time.sleep(2.0); print("2 秒推进", client.frame() - before, "帧")
```

## 八、下命令的硬规矩

1. **坐标先校验**：越界会崩游戏。一律经 `Validator`，别绕过。
2. **不指挥非己方对象**：引擎不拦，且该路径可能崩游戏。
3. **任务类动作走 `UnitOrder`**，不用 `MissionClicked`（后者无条件传格子，多一条崩溃路径）。
4. **一次只验一条没测过的命令**，别把几条新命令串在一局里——上次崩溃就没能隔离到单条命令。
5. **按帧确认生效，不按轮询次数**：实测移动 4 帧、生产 14 帧、部署 17 帧、变卖 3 帧。
6. **暂停时不要下令**：`MicroLayer.run()` 按帧节流会自动避免，直接调 `tick()` 没有这层保护。

## 九、踩坑清单

| 坑 | 后果 | 对策 |
|---|---|---|
| 用 `cmd /c start` 启动 | 静默失败，什么也不发生 | 用 PowerShell 加绝对路径 |
| 端口一通就发命令 | 还没进对局，白忙 | 等 `stage=2` 且有 `current_player` |
| 以为帧不涨就是崩了 | 误判，浪费一局 | 先 `winfocus.py reset` 再判 |
| 脚本内自调 `focus_game()` | 无效，继续暂停 | 用 `winfocus.py reset` |
| 跑批时切窗口 | 游戏暂停，脚本超时 | 用 `focused_batch` 占住焦点 |
| `PlaceQuery.house_class` 传 0 | 报 `invalid house 0` | 给真实 House 指针 |
| `ProduceOrder` 的 action | 三个取值行为相同，暂停/取消无效 | 暂停与取消走 `AddEvent` 的 `Suspend`/`Abandon` |
| 生产/放置看成「对象级」 | 没有对象可传，`Scope` 报错 | 阵营级意图用 `Scope.empty()` |
| 等待上限照 4 帧设 | 部署要 17 帧，会误报超时 | 用 `DEFAULT_MAX_WAIT_FRAMES`（45 帧） |
| 崩溃后不拷报告 | 被下一次崩溃覆盖 | 第一时间 `cp` 到 `.agents/tmp/` |
