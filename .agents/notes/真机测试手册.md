# 真机测试手册

在真机上跑测试的操作流程。环境事实（路径、网络、Python）见[开发环境](开发环境.md)；引擎行为与实测结论见[探针实验结论](探针实验结论.md)、[命令能力测绘结果](命令能力测绘结果.md)；代码接口见[技法框架](技法框架.md)与 `src/ra2agent/` 各模块文档。

只看一页的话，记住三件事：**失焦即暂停**、**恢复焦点必须 `winfocus.py reset`**、**每次只验一条新命令**。

## 二、启动游戏

必须用 PowerShell 与绝对路径，`cmd /c start` 从 WSL 启动会静默失败。

```sh
/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -NoProfile -Command \
  "Start-Process -FilePath 'D:\Games\ra2probe\gamemd-spawn-ra2yrcpp.exe' -ArgumentList '-SPAWN' -WorkingDirectory 'D:\Games\ra2probe'"
```

**约 3 秒后端口就监听，但此时还没进对局**，要等到 `stage=2` 且恰好一个 `current_player`：

```python
import time
from ra2agent.engine.client import Client
from ra2agent.constants import LoadStage

client = Client(); client.connect()
for _ in range(40):
    state = client.get_state()
    mine = [h for h in state.houses if h.current_player]
    if state.stage == LoadStage.INGAME and mine:
        print("进对局：帧", state.frame, "阵营", mine[0].name); break
    time.sleep(3)
```

## 三、焦点：最容易踩的坑

本节说的暂停，只在**全屏 + DDrawCompat** 这套显示配置下成立。换成 cnc-ddraw 的 `windowed=true` 加 `noactivateapp=true` 之后，失焦不再暂停，下面这些约束随之消失——机制与两道墙见 [双实例联机](双实例联机.md)。

- 游戏失焦即暂停主循环：排队命令不执行，帧号不涨；同步命令（读状态）不受影响。
- **恢复主循环需要一次真正的焦点切换。** 已经在前台时再置前不会产生切换，游戏不醒——这是最容易误判成「崩溃」的地方。
- 正确做法是一条命令：

```sh
python3 tools/winfocus.py reset      # 先移开再置前
```

- **跑批期间不要动键盘鼠标。** 你切窗口、打字都会把焦点抢走，游戏随即暂停，脚本会报「帧不推进」。要长时间无人跑批用 `tools/batchkit.py` 的 `focused_batch`，它占住焦点、结束时归还并发系统通知。
- 脚本内不要自己调 `focus_game()`：对已经在前台的窗口无效。跑批前由外层命令 `reset`。

## 四、判定「暂停」还是「崩溃」

| 现象 | 含义 | 处置 |
|---|---|---|
| `GetGameState` 正常、帧号不变 | 暂停（失焦） | `winfocus.py reset` |
| `GetGameState` 超时、端口关闭、进程消失 | 崩溃 | 见第七节留证 |
| 进程约 130 ms 后消失、退出码 0、无转储 | **命中了单实例守卫**，不是崩溃 | 已开着一个实例时属正常；要同时跑两个见 [双实例联机](双实例联机.md) |

命令下发后帧不推进时，执行器报的是 `GameNotResponding`（命令是否生效未知），不是命令失败——**暂停期间排队的命令不会丢，恢复后照常执行**，那时已脱离下令时的语境。

## 五、跑一次测试

把重置焦点与脚本放在同一条命令里，中间不要插入别的操作：

```sh
cd ~/ra2-agent
python3 tools/winfocus.py reset
PYTHONPATH=src:tools python3 .agents/tmp/你的脚本.py
```

脚本骨架：连接 → 取底图与类型表 → 读一帧 → 做事 → 判帧推进。临时脚本放 `.agents/tmp/`（不入库，可随时删）。

```python
from ra2agent.engine.client import Client
from ra2agent.engine.observation import Observer

client = Client(); client.connect()
observer = Observer(client).bootstrap()          # 地图与类型表各取一次
state = observer.poll()
print(state.summary())

before = client.frame(); time.sleep(2.0); print("2 秒推进", client.frame() - before, "帧")
```

## 五点五、让 Agent 上桌

MCP 服务（`src/ra2agent/mcp.py`）可以单独跑，它在 stdio 上讲 JSON-RPC，由 DSH 拉起：

```sh
cd ~/ra2-agent && python3 -m ra2agent.mcp
```

DSH 侧的挂载是 agent preset `ra2`，声明在 [dsh/](../../dsh/)；新建会话时选它即可，细节见[指挥层](指挥层.md#挂载方式)。

**起停游戏也交给 Agent**：`game` 工具管进程本身，游戏没在跑时它照样能用。`game status` 报进程、端口、崩溃留证与焦点；`game start` 立刻返回，服务要几秒、进对局更久；`game stop` 对局进行中要显式 `force`；窗口失焦时用 `game focus` 抢回焦点（等价于 `winfocus.py reset`）。

本手册前四节仍是人手的做法，两者等价——Agent 不在场时照旧手动跑。

挂上之后要注意：跑批期间别动键鼠，失焦会让 `call` 报 `GameNotResponding`；单次工具调用默认
60 秒超时，故 `call` 必须立刻返回，等待是技法层的活。

## 五点七、验收一条链路

验「事件 → 唤醒」这类跨进程链路时，判据要单一且可观测，否则会把「没等到」当成「没通」。

**判据**：给玩家 agent 一条任务，要求它制造某个事件后**立刻停手**（不读 `status`、不调任何工具），看它是否在空闲时收到一条**不是自己调用产生的 user 消息**。收到即通，并要求它原文回传。

**三条硬约束**：

- **事件侦测器只在玩家 MCP 进程活着时存在**，而该进程随模型空闲结算消失。故验收空闲期的唤醒必须另起常驻监听：`PYTHONPATH=src python3 -m ra2agent.watch --player <名册名> --wake-session <agent id>`，它的日志逐条打「帧、是否送达、说明、插件回话」。
- **`status` 的新结果读走即清**。等推送期间读一次 `status` 会把结果消费掉，也让判据分不清「推送」与「自己拉的」。
- **别在验收期间回消息给被测 agent**：一条 `send_message` 就是一次唤醒，与要验的那条路无法区分。

**查投递是否落地**：`WakeBridge` 记的是插件回话而非 HTTP 码（插件用 HTTP 200 + `{"ok": false}` 表示拒绝）；玩家会话转录在 `~/.dsh/sessions/--<项目>--/<agent id>/session.v4.jsonl.zstd`，注入的唤醒带 `source.kind = "ra2-wake"`（该文件是 zstd 压缩，需自备解压工具）。

**同机两个玩家**：每人各起一个监听进程，`--wake-session` 必须是它自己那个 agent id——不点名时插件按「唯一候选」猜，会叫错人。

## 八、下命令的硬规矩

1. **坐标先校验**：越界会崩游戏。一律经 `Validator`，别绕过。
2. **不指挥非己方对象**：引擎不拦，且该路径可能崩游戏。
3. **任务类动作走 `UnitOrder`**，不用 `MissionClicked`（后者无条件传格子，多一条崩溃路径）。
4. **一次只验一条没测过的命令**，别把几条新命令串在一局里——上次崩溃就没能隔离到单条命令。
5. **按帧确认生效，不按轮询次数**：实测移动 4 帧、生产 14 帧、部署 17 帧、变卖 3 帧。
6. **暂停时不要下令**：`MicroLayer.run()` 按帧节流会自动避免，直接调 `tick()` 没有这层保护。

## 九、踩坑清单

| 坑 | 后果 | 对策 |
|---|---|---|
| 用 `cmd /c start` 启动 | 静默失败，什么也不发生 | 用 PowerShell 加绝对路径 |
| 端口一通就发命令 | 还没进对局，白忙 | 等 `stage=2` 且有 `current_player` |
| 以为帧不涨就是崩了 | 误判，浪费一局 | 先 `winfocus.py reset` 再判 |
| 脚本内自调 `focus_game()` | 无效，继续暂停 | 用 `winfocus.py reset` |
| 跑批时切窗口 | 游戏暂停，脚本超时 | 用 `focused_batch` 占住焦点 |
| `PlaceQuery.house_class` 传 0 | 报 `invalid house 0` | 给真实 House 指针 |
| `ProduceOrder` 的 action | 三个取值行为相同，暂停/取消无效 | 暂停与取消走 `AddEvent` 的 `Suspend`/`Abandon` |
| 当成崩溃的是单实例守卫 | 查一轮崩溃白费 | 进程约 130 ms 后干净退出（rc=0、无转储）就是它；见 [双实例联机](双实例联机.md) |
| 用 `spawn.ini` 的 `PlayerCount` 声明对手 | 静默退回单机，加载界面只有一个玩家 | 对手写在 `[Other1]` 段 |
| 第二游戏目录漏掉子目录 | gamemd 启动即静默退出 | 整目录复制；只对只读大文件用硬链接 |
| 把硬链接共享的旧文件当新证据 | 误判方向 | 先看时间戳与 inode |
| 生产/放置看成「对象级」 | 没有对象可传，`Scope` 报错 | 阵营级意图用 `Scope.empty()` |
| 等待上限照 4 帧设 | 部署要 17 帧，会误报超时 | 用 `DEFAULT_MAX_WAIT_FRAMES`（45 帧） |
| 崩溃后不拷报告 | 被下一次崩溃覆盖 | 第一时间 `cp` 到 `.agents/tmp/` |
| 把 `expose` 当自动层的闸 | 事件触发的技法被自己人拒掉，唤醒一局都不通 | `expose` 只在模型面拦；自动层看 `trigger` |
| 只看 HTTP 码判唤醒成败 | 插件回 `{"ok": false}` 也记成已送达，那条说明被清出待发队列、永久丢掉 | 读回话里的 `ok`（`wake._verdict`） |
| 在玩家 idle 时期待事件唤醒 | 侦测器随玩家进程消失，事件发生了也没人发 | 另起 `ra2agent.watch` 常驻监听 |
| 验收期间读 `status` 或回消息给被测 agent | 判据被污染，或新结果被消费掉 | 停手等推送，判据只看「非自己产生的 user 消息」 |
| 拿 `observation.own` 判单位损失 | 完工待放置进 limbo 会被误判成损失 | 查 `state.objects` 里指针在不在 |
| 在 `rulesmd.ini` 里找 `Foundation=` | 找不到，它定义在 `artmd.ini` | 落点交给引擎的 `PlaceQuery`，且**一栋一问** |
| INI 只按 `;` 去注释 | `//` 注释的节头认不出，整节并进上一节（实测毁了一个弹头数据） | `rules.py` 的 `strip_comment` 两种都认 |
| 一条 `_sites_for` 问所有待放置建筑 | 第二栋显示第一栋的落点，被读成「2×2 与 3×3 混给」 | 一栋一问，各带方位与距离 |
| 可造清单按造价升序 | 大件被上限截掉（实测重工看不见却可造） | 能造的贵在前、缺前提的便宜在前 |
