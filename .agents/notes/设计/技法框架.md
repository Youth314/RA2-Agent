# 技法框架

L0 只做基础设施，其上的能力由模型自己写成**技法**（tactic），按需组合。层的边界事先定不出来，改由组合与封装自然形成。

## 三层

| 层 | 名称 | 时间尺度 | 决策者 | 产出 |
|---|---|---|---|---|
| 0 | 基础设施 | 游戏帧 | 固定代码 | 引擎命令 |
| 1 | 技法 | 每 tick 22–45 帧 | 模型与人离线写，运行时确定性执行 | 意图 |
| 2 | 指挥 | 模型自定 | LLM；人经对话介入 | 选技法、给参数、定目标 |

**技法层按独立节奏推进，前提是承载 L1 的 MCP 进程仍存活。** 玩家子 agent 作用域释放后，其 MCP、在管任务与自动层不由 watcher 接续；普通 preset 的共享进程具有不同生命周期，见[DSH 测试接入审计](../验证/DSH测试接入审计.md)。寻路与自动开火由引擎负责。

## 意图与技法

**意图是要什么，技法是这样做。** 两个方向的词汇不同：

| 方向 | 形态 | 理由 |
|---|---|---|
| 指挥 → 技法 | 通用信封：技法名 + 参数 + `scope` + TTL | 模型要能加新能力，封闭的 kind 集合会把它挡死 |
| 技法 → 基础设施 | 类型化封闭集合：`MoveTo`、`Hold`、`Attack`、`Produce`、`Place`、`Sell` | 对应固定的引擎能力，类型约束能在发送前拦错 |

指挥层意图复用 `Intent` 信封（`id`、`parent`、`layer`、`issuer`、`scope`、`created_frame`、`ttl_frames`、`state`），载荷为 `TacticCall{tactic, params}`。

## 接口

```python
class Level(StrEnum):
    NORMAL = "normal"      # 正常玩法
    EDGE = "edge"          # 时序与边界技巧，人也能做
    EXPLOIT = "exploit"    # 明确 bug，人难复现
    CHEAT = "cheat"        # 只有 Agent 做得到：读全图、伪造事件、直接加钱

class Mode(StrEnum):
    MATCH = "match"        # 对战：只看卡片
    OFFLINE = "offline"    # 离线：卡片加 L0 的 API 与源码

@dataclass(frozen=True)
class Param:
    name: str
    default: object
    help: str
    check: Callable[[object], bool] | None = None   # 取值检查，受理时执行

# 内置检查：is_cell、is_stance、is_non_negative_int、is_positive_number

@dataclass(frozen=True)
class TacticInfo:
    name: str                        # 唯一名，模型按它引用，如 "advance_to_cell"
    summary: str                     # 一句话，进卡片
    layer: Layer = Layer.L1_TACTIC
    params: tuple[Param, ...] = ()
    requires: tuple[str, ...] = ()   # 适用条件标签
    level: Level = Level.NORMAL
    expose: bool = True              # 是否进对战时的卡片；零件设假
    source: str = "builtin"          # builtin / model / human
    version: int = 1

@dataclass(frozen=True)
class Tactic:
    info: TacticInfo
    run: Callable[[TacticContext], tuple[Intent, ...]]

class TacticContext:
    """一次调用拿到的全部东西。技法只读，不做 I/O，只返回意图。"""
    observation: Observation         # 尊重迷雾的一帧
    subject: Squad                   # 本层管的对象，只读
    params: dict                     # 本次调用的参数
    frame: int                       # 当前游戏帧
    attempt: int                     # 第几次尝试，卡住重来时递增
    memo: dict                       # 跨帧记事本，按技法与键隔离，任务结束清空

    def call(self, name, *, optional=False, **params) -> tuple[Intent, ...]:
        """调用另一条技法。必须经此，门控、适用条件、深度与调用链日志都在此生效。
        `optional=True` 只放行适用条件，不放行等级门槛。"""

    def intent(self, cls, *, scope=None, **payload) -> Intent:
        """造一条给基础设施的意图：层、帧号、涉及对象自动填好。"""

class TacticRegistry:
    def register(self, tactic: Tactic) -> Tactic: ...
    def load_builtin(self) -> TacticRegistry: ...            # 返回自身，便于连写
    def cards(self, mode, observation=None, subject=None) -> list[Card]: ...
    def run(self, name, *, observation, subject, params=None, frame=0, memo=None,
            log=None, attempt=0) -> tuple[Intent, ...]: ...
    def catalog(self) -> str: ...        # 人类可读清单
    def fingerprint(self) -> str: ...    # 库指纹，写入决策日志

@dataclass
class TacticPolicy:
    max_level: dict[Layer, Level]    # 每层的等级门槛
    enabled: frozenset[str]          # 空集表示不额外限制
    disabled: frozenset[str]
    max_depth: int = 8               # 调用链深度上限
    max_calls: int = 32              # 一次顶层调用的技法次数上限
    max_intents: int = 32            # 一次顶层调用的意图数上限
    timeout_ms: int = 50
    def allows(self, info: TacticInfo) -> bool: ...
```

## 自动触发

技法在名片里声明 `trigger` 后可以**自己跑**，不必等模型下令——LLM 的响应时间配不上
实时游戏，开局该发生的事不该等它思考。产出是**脉冲**：跑一次、下发一次、不建编队。

脉冲而非任务的三个理由：房子级动作（造电厂一类）不需要单位，而任务模型是「一队
单位 + 意图」；给 `Produce` 绑一队单位会让它每拍重发、重复下单；脉冲也不会长期占着
单位的租约，模型随时还能自己指挥它们。

需要持续控制单位的技法（推进、缠斗）仍由模型显式 `call`。

**自动触发与模型调用共用注册表的等级、启用与适用条件门控。** 自动层直接执行脉冲，在 Commander 接入中默认排除在管单位；Micro 与 Auto 共用操作对象 / scope 校验，Micro.assign 也拒绝重叠租约。范围与例外见[接口离线验证](../验证/MoveStop接口离线验证.md)。自动触发的技法不能有必填参数，登记时拒绝此类声明。

**唯一的例外是 `expose`，它只在模型面生效**：`expose=False` 的技法不进卡片、模型 `call` 被拒，但自动层照跑（`TacticRegistry.admit()` 不看它，`automatic()` 只看 `trigger`）。曾经把 `expose` 当自动层的闸，于是 `report_trouble` 被触发命中后又被自己人拒掉，唤醒整条链一局都没走通。

**事件驱动的技法拿得到当拍事件**：`ctx.events` 给的是这一拍新合成的事件（只有自动脉冲有；编队任务为空，否则同一件事会被每条在管任务各报一次）。`report_trouble` 靠它把「出什么事了」写进唤醒文案。

**等待必须有上限**：条件不满足、或条件成立却产不出意图时，任务进入等待——同一理由连续等满 `WAIT_GRACE_FRAMES` 就收工并报「等了 N 帧局面没变」，耗时由名片字段 `wait_grace_frames` 覆盖（自带 `max_frames` 的 `guard_area` 设为 `None` 豁免）。同类告警按 `NOTICE_EVERY_FRAMES` 限频，理由一变立刻放行。此前只记不结：一条等建筑完工的任务能永久占着单位，而每拍都发同一条告警（实测单次 `status` 堆过 20 条）。

**「没事可做」与「等下一拍」要分开**：两者在代码上都是 `run` 返回空元组。名片字段 `idle_ends_task` 为真时当场结算为 `idle` 并交还单位（`deploy_mcv` 对已展开的建造厂或非基地车）；默认继续等（`guard_area` 没目标时不下令，靠自己的 `max_frames` 收尾）。

自动命中不等于该做事：`run` 里判完可以返回 `()`。空转是正常的、不报给模型的；只有
真下发了意图或出错才会出现在 `status` 里。

## 安全

| 机制 | 做法 |
|---|---|
| 等级判据 | 对称性：人类在同一版本、不开挂能做到的算技法；只有 Agent 因能读内存、注入事件才做得到的算作弊 |
| 两道闸 | 上下文闸（不进卡片）加执行闸（调用时报错，不静默跳过） |
| 等级穿透 | 有效等级取整条调用链的最大值；内层调用必须经 `ctx.call`，不得直接 import |
| 深度与环 | 调用深度上限；调用链内同名即拒绝 |
| 意图总量 | 一次顶层调用产出的意图数上限 |
| 异常隔离 | 技法抛异常只废掉这一次调用，记录后继续 |
| 运行时限 | 深度与总量在代码层限死；墙钟超时用 `SIGALRM`（运行时位于主线程时有效），否则退化为耗时统计与连续超时停用 |
| 静态检查 | 技法源码只许白名单 import；禁 `open`、`eval`、`exec`、网络与进程 |
| 不碰引擎 | 技法只返回意图，下发一律经 `Validator` 与 `Executor` |

## 可见面

| 模式 | 模型能看见 | 能做什么 |
|---|---|---|
| 对战 | 顶层卡片：名字、一句话、参数、适用条件 | 发指挥层意图 |

## 技法状态

`subject` 只读，技法不改状态；状态由运行时按返回的意图与观测更新。需要跨帧记忆时用 `ctx.memo`，按技法与键隔离，任务结束清空。

## 运行时

技法只回答「这一步该下什么命令」，运行时（`micro.py`）负责其余：

| 事项 | 规则 |
|---|---|
| 下令时机 | 只给「还没下过令」或「卡住要换路点」的单位下令，不重复下发 |
| 到位 | 与目标格的切比雪夫距离不超过宽容（默认 1 格，引擎在目标格被占时会停在邻格） |
| 卡住 | 位置连续 90 帧不动即换路点，`ctx.attempt` 加一，技法据此换落点；超过重试上限判失败 |
| 命令失败 | 对象消失或 mission 非法：该单位失败；其余服务端错误：整队失败 |
| 超时 | 保留结果未知的请求，停止同任务下令；后续判据匹配再推进，不自动重发 |
| 窗口失焦 | MCP 同帧不推进任务；已提交但未确认的命令保留未知，恢复后先观测 |
| 结算 | 全体完成才 `satisfied`，部分损失或失败记 `failed` 并保留逐单位结果；TTL 到期记 `expired` |

结算记录进决策日志，也留在运行时里供上层查询。

## 验证

回放验证是「沉淀」缺的那一环：模型写完技法，得先在一局真实局面上证明它该出手时出手、
发出的命令能过前置校验，才谈得上注册。`replay.py` 给两件事：

```sh
# 录一段真局（游戏在跑时）
python3 -m ra2agent.replay --record --out scenario.json --frames 60 --interval 0.5
# 回放：把这条技法放进录下来的局面里跑，出一份判定
python3 -m ra2agent.replay scenario.json --tactic advance_to_cell \
    --units 213 --params cell=112,60 --ticks 10 --expect-settle satisfied
```

判定看三件事：**有没有在不该出手时出手**（期望里可要求最少产出几条意图）、**命令过不过
前置校验**（回放里命令先过真的 `Executor.plan`，越界坐标与非己方对象会被当场抓住，不
用拿游戏冒险）、**结算落在哪**（satisfied / failed / expired）。

时间线是「一帧一拍」，与真机约 2 Hz 的节拍大致相当。录制里若包含下令之前的静止帧，
卡住判定会先触发一次换路点——那是真实行为，不是回放出错。

**验链路要用真技法**：`TacticRegistry.load_builtin()` 取库里的那一条，别只测临时造的假技法——假技法的名片默认值与真技法不同，实测因此漏掉一个闸：`report_trouble` 是 `expose=False`，自动层选中它后被 `admit` 的 expose 闸拒掉，而测试用例里的假技法默认 `expose=True`，一直绿。

## 生命周期

草稿 → 静态检查 → 按能力选择必要验证 → 注册进库 → 统计使用与成败 → 废弃。回放适用于固定观测下的决策与结算；原版效果、动态行为和宿主生命周期使用对应真机或集成验证，不要求每项能力先录制完整对局。

每条技法带 `version`；一局开始时把库指纹写入决策日志，复盘可重现当时的能力集合。

## 示范技法

参数与适用条件以 `tactics` 卡片为准（那由代码生成），本表只说形态。

| 名 | 说明 | 等级 | 暴露 | 自己跑 |
|---|---|---|---|---|
| `deploy_mcv` | 展开未展开的基地车 | normal | 是 | 每 30 帧 |
| `report_trouble` | 出事（掉单位、断电、被渗透、出局、建筑完工）时把模型叫回来看 | normal | 否 | 事件触发 |
| `build_structure` | 让建造厂生产一栋建筑 | normal | 是 | 否 |
| `train_unit` | 让某个厂生产一种单位 | normal | 是 | 否 |
| `place_ready_building` | 放下已完工的建筑；不给 `cell` 由 L0 问引擎要一格 | normal | 是 | 否 |
| `advance_to_cell` | 把这队单位推进到目标格附近，逐单位展开队形 | normal | 是 | 否 |
| `advance_covering` | 组合示范：先接战判定，无敌人再推进 | normal | 是 | 否 |
| `hold_position` | 发出 STOP；不承诺原版警戒或永久保持位置 | normal | 是 | 否 |
| `hold_and_fire` | 对半径内最近可见敌人发 Attack，可能追击；无目标时 STOP | normal | 是 | 否 |

| `engage_nearest` | 对半径内最近的可见敌人开火 | normal | 是 | 否 |

| `retreat` | 脱离接触退回基地或指定格 | normal | 是 | 否 |

## 验证范围

回放使用真实 Executor.plan 和合成执行结果，不发送游戏命令，也不运行真实生效谓词；它可验证固定观测下的意图、前置校验和结算，不能证明原版操作效果。测试方式与人工协作原则见[能力验证方法](../验证/能力验证方法.md)。
