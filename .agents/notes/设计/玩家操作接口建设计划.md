# 玩家操作接口建设计划

更新日期：2026-10-03。状态：用户已接受的目标与实施计划，具体 API 名称、schema 和各批能力范围待执行时定稿。A0 已完成仓库审计与首组契约收敛，A1 从受控 Stop 切片推进。本计划细化[总体演进计划](L1基础能力与技法演进计划.md)中基础接口与技法接入的工作，不代表新增能力已实现。

## 1. 建设目标

以[玩家操作能力表](../引擎/玩家操作能力表.md)的 U01–U15、P01–P06、B01–B13 共 34 个能力条目作为覆盖目录，建设供 L1 使用的受控玩家操作接口。接口表达玩家能下达的操作及其目标、修饰和计划语义；ra2yrcpp 负责适配实际游戏路径，技法在此基础上选择对象、组织步骤、管理目标和处理异常。能力条目不要求与函数或公开技法一一对应。

调用边界为模型 → 技法 → 玩家操作意图 → L0 校验与执行 → ra2yrcpp 适配层 → 游戏。模型始终只调用技法，基础接口首先服务 L1；需要公开的单项操作再封装为薄技法。基础操作的覆盖度与模型可见技法数量分别管理。

“与玩家能力一致”指操作表达、原版规则下的效果和合法信息范围一致。单位选择可用稳定 ID 表达，无需让模型逐次模拟 UI 选择或键盘输入。原版寻路、接敌、采矿往返及单位多态行为交给游戏；队形、战略目标、持续维修保障和经济管理由组合技法负责。以玩家可获得的信息为边界回读状态，不借接口读取隐藏敌方目标；诊断字段与 L1 合法观测分开。

### 可验收目标

| 目标 | 完成标准 |
|---|---|

| 第一组可用接口 | A1 中明确选定的单位/目标范围完成操作契约、L0 执行、必要回读、相关测试及至少一个正式技法使用入口；未覆盖类型继续明确拒绝或标未知 |
| 逐步达到玩家能力覆盖 | 各条目在声明支持的版本、单位状态和目标范围内可执行并有对应效果证据；范围缩减须说明原因，不能静默移除难实现的玩家能力 |
| 可复用的技法基础 | 组合技法通过同一受控接口构建行为；输入回执与任务目标完成分开，基础操作不被默认逐拍重发 |
| 可继续维护 | 能力表维护事实与证据，接口规格维护契约，本计划维护顺序，验证记录维护具体结果，交接提供唯一当前入口 |

## 2. 现有基础与关键差距

GuardCurrent/GuardPosition、身份复查和受控回执可复用，当前范围见[Guard 接口验证](../验证/Guard接口验证.md)。native_guard、CMIN 的 harvest/auto_harvest 及普通 DSH 四项限定联调已完成，见[技法迁移](../验证/Guard技法迁移验证.md)和[DSH 联调](../验证/GuardDSH联调验证.md)。既有 Executor、Validator、Micro、Autopilot、稳定 ID 和租约作为实施基础，按契约差距增量调整。

首批须处理的语义问题包括：玩家 S 使用 Idle 事件，现有 UnitOrder.STOP 使用 ClickMission(Mission_Stop)，全语义等价尚未确认；MoveTo(hold) 忽略目的地，不能代表“走到后驻守”；AttackMove 仅凭 destination 匹配不能确认移动模式；Attack 仅凭 Mission.ATTACK 不能确认攻击了指定对象。既有测试证明相应执行链，不自动证明玩家等价。证据与现状详见[能力表](../引擎/玩家操作能力表.md)和[契约审计](../../drafts/接口/L1基础接口契约与现状审计.md)。

对象护送、建筑保护、动态乘员/模式与原版计划仍有接口或观测缺口。CMIN 的 G 不等于指定矿区采矿；Engineer-FV 一次追随维修不保证永久护送。guard_area 的自选敌策略可作为组合能力保留，不能充当原版 Guard 定义。

## 3. 接口规格必须回答的问题

下表是 A0 的契约检查表；具体类型和方法名称在现有[契约草案](../../drafts/接口/L1基础接口契约与现状审计.md)中收敛，不预先建立一套独立框架。

| 方面 | 必须明确 |
|---|---|
| 操作目录 | 玩家操作 ID、语义、目标类型、适用范围；Move/AttackMove/Stop/Guard 等概念明确，不能靠含混 stance 承诺不同操作 |
| 请求 | 稳定 actor ID、类型化目标、必要修饰、依据帧、局次与请求关联；复用现有信封，按本批需要补字段 |
| 动态适用性 | 区分接口支持与当前对象能否执行，返回 yes/no/unknown 和理由；多单位按单位说明，保持首版 Guard 单车辆限制直到单独扩展 |
| 执行与回执 | 发送前和游戏线程可行范围内复查身份/归属/状态；区分提交、拒绝、观察到输入、效果及未知；没有服务端依据不能声称 applied 或 exactly-once |
| 后续观测 | 每项操作列出最少必要目标、模式或行为字段及合法信息来源；按当前能力增补，不一次性暴露整个游戏内存 |
| 生命周期 | 单次操作如何结算，原生行为如何继续，租约何时释放，自动层何时接管；cancel 默认不等于 Stop，未知结果不盲重发 |
| 批量与计划 | 多单位部分结果、替换与追加分别定义；批量受理不等于原子或同帧执行，原版计划与运行时逐段调度分别声明 |
| 兼容与公开 | 旧技法/意图的语义映射、迁移方式、DLL 能力版本与降级行为；缺能力明确报告，兼容替代必须注明语义差异 |

能力查询可先由可靠静态信息与已回读动态状态组合实现，未知保留 unknown。U15 的原版上下文查询须核验副作用和 UI/按键依赖，不作为所有新接口的前置阻塞项，也不直接增加模型工具。

## 6. 每批验收与协作

相关切片组成一个功能组，统一交付操作契约、最少必要观测、受控适配、L1 使用入口、相关证据、明确限制与可恢复的交接。功能组完成后集中构建和真机验证，按根 AGENTS.md 与能力验证方法选择检查，复用未受影响的既有结果；未验矩阵不作为全部补齐的前置。测试选择以能回答当前问题为准：离线验证编码/校验/状态与结算，真机验证新操作或新效果，真实 DSH 只在宿主接线改变或证据需要时加入。方法见[能力验证方法](../验证/能力验证方法.md)。

判据包括：合法操作可执行；关键不适用输入明确拒绝；状态已有、结果未知和部分成功可区分；输入确认不冒充到达/击毁/维修完成；原生持续行为不被无条件重发打断；模型与自动层的控制归属可解释。只有本批声明的单位、目标、版本和场景通过，才扩大支持声明。既有回归按改动影响选择，不重复无关全量测试，不为单次实验建立通用测试平台。

原版效果或联机行为需要补证时，以人工操作、只读采集和已有逐帧录制优先；瞬时输入不能只凭低频采样缺席判断失败。用户可准备单位、操作按键或观察画面。提出协作请求时说明目的、具体步骤、结束判据及等待期间的工作；没有独立工作则明确仅等待。

本机任何修改提前说明内容、位置和原因。既有 Guard DLL 的长期部署授权、指纹与回滚见[部署记录](../环境/Guard部署与联调.md)；该授权不能扩展为任意新 DLL 或环境设置的长期替换。涉及新版本部署、安装或宿主配置改变时，先准备具体产物、影响和回滚，再按用户要求解释并确认。仓库内已授权的可逆实现与文档修订按告知后推进。

持续暂停恢复、完整 DSH idle/dispose、玩家子 Agent 冷恢复、完整联机同步及跨局身份契约仍未验证，作为相应问题的限制保留。HARV 与新接口空 FV 对照已按用户决定取消，除非新的具体缺口确需该证据，不重新列为默认前置。
