# 指挥层

模型与游戏之间的那道门。门内是技法层（`src/ra2agent/command.py`），门外是游戏进程本身（`src/ra2agent/deploy/game.py`）。

## 形态

**工具数固定，能力数随技法库增长。** 技法从 5 条长到 200 条，模型看到的永远是这五个工具；库里有什么写在卡片上，不在工具名上。

| 工具 | 做什么 | 返回 |
|---|---|---|
| `status` | 读局势：一行摘要、在管任务、上次读过之后的新结果与告警 | 文本 |
| `tactics` | 读卡片：此刻用得上的技法，可按关键词筛 | 若干行 |
| `call` | 下达一到多条任务，**立刻返回不等待** | 每条一行受理结果 |
| `cancel` | 撤销在管任务，交还它占用的单位 | 每条一行 |
| `game` | 管游戏进程本身，游戏没在跑时也能用 | 若干行 |

前四个是**局内**的，随技法库长；`game` 是**门外**的，只有四个固定动作，两边都不随对方膨胀。

`call` 受理不等于提交或完成。`status` 分别报告在管任务、命令观测回执、结果未知与任务结算；观测匹配不证明本次请求造成变化。字段与完成依据见[接口离线验证](../验证/MoveStop接口离线验证.md)。

## 门外：游戏进程

游戏没开时四个局内工具都无从下手，故 `game` 不依赖对局连接。

| 动作 | 做什么 |
|---|---|
| `status` | 进程、端口、窗口焦点；崩溃留证只在与本次启动有关时报；已经连着时再报一行对局 |
| `start` | 起游戏，**立刻返回**——服务要几秒、进对局更久，进展由 `game status` 报 |
| `stop` | 停游戏并丢弃整条会话；**对局进行中要显式 `force=true`** |
| `focus` | 恢复焦点；失焦是否暂停取决于显示配置，主循环状态按游戏帧判断 |

**刚 `start` 完那几秒不算崩。** 进程在、端口还没通是正常启动过程；此时若报一份旧报告，模型会把「正在启动」读成「崩过」——实测就这么误判过一次。故崩溃报告必须比本次启动新才算数，状态行也改成「正在启动（已等 N 秒）」，超过一分钟才提示可能卡住。

三条定死的规矩：

- **用户没说要玩，模型不自己 `start`。** 起游戏会抢焦点并常驻一条连接，这条写进了工具说明。
- **对局中停要 `force`。** 关掉游戏丢掉的是当局与决策日志，属于不可逆动作，故常见情形一个词就完，破坏性动作要显式。
- **只有固定动作，没有通用 shell。** 一旦能跑任意命令，`一切动作都过技法层与 Validator` 这条底线就绕过去了。

`start` 与 `stop` 都会丢弃整条会话（连接、观测器、技法层、决策日志）。游戏停过再起，帧号归零、地图与单位指针全变，旧的观测器一律不能留。

局内工具在连不上时不再抛 `ConnectionRefusedError`，而是一句「游戏没在跑：……。用 game status 看进程，game start 启动。」

## 受理时就把话说清楚

`call` 会做一遍技法层同样的校验，任一项不过就当场拒绝并说明原因，而不是让它静默空转：

| 拒绝原因 | 例子 |
|---|---|
| 没有这条技法 | 名字拼错 |
| 零件不对指挥层开放 | `halt` 只能被组合技法调用 |
| 等级超出门槛或已被停用 | `exploit` 档默认关 |
| 此刻用不上 | 视野里没有敌人却调接战技法 |
| 参数不对 | 缺 `cell`、多给了不认识的字段 |
| 单位不对 | 不是你方可用单位 |

批量下达每条独立受理，允许部分成功。

## 事件只报一次

`status` 报「上次读过之后」新结算的任务和运行时告警（失焦暂停、条件变化导致空转），读走即清空，免得模型每拍重看同一批。在管任务每次都报，不消耗。

**事件是从相邻两帧的状态差合成的**，不是引擎通知：电力由足转不足、余额跌破阈值、三方渗透标志由假变真、参战方出局、己方对象从地图上消失（`state.objects` 里查不到指针才算损失；完工待放置进 limbo 不算）、新出现完工待放置的建筑。合成判据见 `src/ra2agent/engine/events.py`。

**没送出去的唤醒会报，送成功的不报**——那条 user 消息本身就是通知。

## 本局信息

`status` 首次报一次本局简报（地图尺寸与水域占比、参战各国与人类/电脑、科技等级），之后每拍只带一行「本局｜…」。

**游戏性质与地图名取不到**：引擎 proto 里的 `GameSettings`（含 `map_name`、`game_mode`、`players[]`、`start_credits`、`short_game`、`superweapons`）在上游 C++ 源码里一处都没实现，没有任何命令能取。故现在只有水域占比这一个线索，海战图看得出，生死斗与作战分不出。

报告形状固定，便于模型比较两次之间的变化，也便于日后复盘。

己方和合法可见敌方对象行提供当帧 health，己方另提供经过合法投影的 actual_target；无目标、不可观测和旧 DLL 未提供分别显示。新结果显示 completion_basis 及最近回执的允许观测字段，不将 operation_observed 解释为击毁或持续接战。输出契约、信息边界和离线证据见[玩家状态输出验证](../验证/玩家状态输出验证.md)。

## 电力、建造与落点

`status` 另报三样，此前模型对基地的产能状况一无所知：电力水位（`power_drain/power_output`，入不敷出时标注）、每个工厂一行生产进度（在造类型、`progress_timer/54`、是否完工待放置、是否暂停）、以及完工待放置的建筑。

**在造类型不必给 `Factory` 新增字段**：`Factory.queued_objects` 是对象指针元组，而同一个对象就在这一帧的 `state.objects` 里（工厂内的对象即落成后的对象，指针从生产到放置不变），故拿指针回查类型表即可。

**落点由指挥层查、模型挑**：合法格只有引擎说了算（`PlaceQuery`），而技法不做 I/O、观测层只读，故由 `status` 替模型问一次并附上「可选落点」，模型挑一格作为 `place_ready_building` 的参数回传。查询结果按帧缓存，引擎报错也缓存一个 TTL——否则每次读局势都是一次真机往返。

**完备性依赖技法库**：一个单位可寻址不等于可指挥。完工待放置的建筑停在 limbo 里、不在 `observation.own` 中，故 `UnitPool` 额外收一份 `pending`：`agent_id()` 认它（否则谁也发不出 `Place`），但 `agents()` 不报它（它不是可用单位，不该被派去移动或攻击）。

## 可见面

| 模式 | 模型能看见 | 能做什么 |
|---|---|---|
| 对战 | 五个工具与卡片 | 下达指挥层意图，起停游戏 |
| 离线 | 卡片加零件的完整清单、L0 的 API 与源码 | 写与验证技法 |

对战模式看不到零件、看不到技法源码、看不到原始帧（单帧 11.9 KB，只给摘要），也**没有任何直接发引擎命令的工具**——这是安全底线：一切动作都得经过技法层与 `Validator`。

## 叫醒模型

模型可通过 status 主动读取结果，或由事件唤醒开启新回合。自动层持续执行要求承载 L1 的进程存活；DSH 玩家子 agent 释放后不能保证此条件。

**链路**：事件触发的技法（`report_trouble`）或常驻监听产出 `Wake` 意图 → `WakeBridge`（限流、合并、记账，参数见 `config/wake.json`）→ POST 到 DSH 的 `/ra2/wake` 路由 → 桥插件把一条 user 消息写进指定会话 → 模型开新一轮。

**三道坎，都是实测踩出来的**：

- `expose` 只在模型面生效：`expose=False` 的技法不进卡片、模型 `call` 被拒，但**自动层照跑**。
- 桥插件用 **HTTP 200 + `{"ok": false}`** 表示「能解析但拒绝」（会话不存在、持久化未确认）。只看 HTTP 码会把失败记成已送达，那条说明随即被清出待发队列、**永久丢掉**；桥现在读回话里的 `ok`，并把 `error` 取成人话。
- **会话必须点名**：`--wake-session` 用 `play_as_*` 返回的 agent id。同机两个玩家时不点名，插件按「唯一候选」猜会叫错人。

**玩家接入需要明确进程生命周期。** dsh-players 的 MCP 随玩家 agent 作用域释放；普通 ra2 preset 的 MCP 按修订版共享，不必随模型回合结束退出。watcher 只负责侦测与唤醒，不接续 L1 任务；已释放玩家子 agent 的冷唤醒路径存在静态缺口，见[DSH 测试接入审计](../验证/DSH测试接入审计.md)。常驻监听入口为：

```sh
cd ~/ra2-agent && PYTHONPATH=src python3 -m ra2agent.watch \
  --player Alpha --wake-session <play_as_alpha 返回的 agent id>
```

它只读局势、用与技法层**同一份判据**（`report.watched_only`）挑事件、投唤醒，不提供工具、不下命令。日志逐条打「帧、是否送达、说明、插件回话」。

**唤醒是稀缺资源**：一次唤醒就是一轮 LLM 调用，故一局限次、两次之间有最小帧距，被挡下的内容攒进待发队列、下次并成一条投出。投不出去（含插件明说失败）不丢，留在队列里重投，并在 `status` 的「唤醒未送达」段报出来。

## 两条约束

- **暂停时不下令是执行要求。** MCP 已改为先读取最新活动对局观测，仅帧推进才调用 tick；退帧或席位变化丢弃旧任务。tick 仍是内部单拍入口，直接调用者须门控；实现与竞争窗口见[接口离线验证](../验证/MoveStop接口离线验证.md)。
- **模型自己安排查看节奏。** 有在飞任务就短看，空闲就长看；事件唤醒是补这条路，不是替代它。

## 真机验证

假模型脚本对着真局跑过一轮，四个局内工具都验了：

| 验的 | 结果 |
|---|---|
| `status` / `tactics` | 文本可读，卡片按局面筛（无敌人时接战技法不出现） |
| `call` 受理 | 两辆车推进到 6 格外，两拍后 `satisfied`，到位 2；命令 3 帧生效 |
| `call` 拒绝 | 无敌人调接战报「此刻用不上：has_enemies」；伪造单位 id 报「不是你方可用单位」 |
| `call` 参数取值 | `cell: null` 当场报「取值不合法」，不再等技法里抛 TypeError |
| TTL | 60 帧的任务按约到期，结算记 `expired`，不计到位 |
| `cancel` | 随即撤销，结算记 `superseded`，到位 0 |

**参数取值必须在受理时校验**：只查「在不在」时，`cell: null` 会一路走到技法里才抛
TypeError——异常隔离兜得住，但模型拿到的是一句看不懂的报错。`Param` 因此加了
`check` 字段，内置 `is_cell`、`is_stance`、`is_non_negative_int`、`is_positive_number`。

## 挂载方式

**当前形态**：一个 agent preset `ra2`，声明在 [dsh/](../../../dsh)。选中它的会话同时具备原有编码能力与五个游戏工具，即目标形态的那个「一个 Agent」。

**技法 skill 不接线**：`skill-filesystem` 扫会话项目根下的 `.agents/skills`，故会话 cwd 落在 `~/ra2-agent` 时 `ra2-write-tactic` 自动出现，卡片里的相对链接也指向仓库内的真实文件。

**为何是 preset 而非 profile 级 insert**：profile 级其实是**全局共用一个** MCP 进程（一次激活），代价是**每个会话**——包括写 DSH 代码的——都会看到红警那五个工具的 schema 与说明，白付 token 与注意力；preset 只让选中它的会话付这份。代价是 preset 的 `plugins` 是完整清单、不能引用别的 preset，故 `ra2` 整份抄自 DSH 自带的 `cordis`，DSH 升级不会自动跟进——用 `python3 dsh/generate.py --check` 查同步。

**安装**：`plugin_manager` 的 `install_bundle`，目标写 `/home/youthz/ra2-agent/dsh`；它把该 bundle 加进 `~/.dsh/profiles/web/package.json` 的 `dependencies` 与 `dsh.profile.bundles`，profile 的 patch 文件不用手改。

**选用**：GUI 的 General 设置里把默认 preset 设为 `ra2`，或新建会话时选它；已在跑的会话保持它启动时的 preset。

**会话与进程**：一个 preset **修订版**共享一个 MCP 进程——开多少 ra2 会话都只有一个，新建修订版才会多一个。修订版只在预设被**重新注册**时新建（装或启停 bundle、GUI 改预设、重启 DSH）；改 `dsh/cordis.patch.yml` 的文件内容既不生效也不新建。旧修订版只要还有会话绑着就不回收，故**改完 `dsh/` 或 `src/ra2agent/` 后重启 DSH，不要用「关掉 bundle 再打开」热换**——那会留下一个跑旧代码的第二进程。

## 接入 DSH

Python 侧是 MCP 服务（`src/ra2agent/mcp.py`，JSON-RPC over stdio，只用标准库）：

- **启动时不连游戏**：DSH 会先用临时探针进程列工具，那时游戏可能没开。连接在第一次
  调用工具时建立，随后由后台线程按约 2 Hz 推进技法层。
- **`call` 立刻返回**，不等生效——单次工具调用默认 60 秒超时，等待是技法层的活。
- **连接持续持有**：GameSession 重置或进程退出时释放连接。上游支持多连接，但部署 DLL 的有效限数与并发稳定性待验证；不能据此禁止所有额外只读连接，也不能允许多个控制者同时下令，见[DSH 测试接入审计](../验证/DSH测试接入审计.md)。
- stdout 只放协议消息，日志走 stderr。

DSH 侧是 `dsh/cordis.patch.yml` 里 preset `ra2` 的一条子条目 `mcp-ra2`，挂的是已装的 `@deepseek-ai/dsh-mcp-client`：`serverName` 取 `ra2`（工具名因此是 `mcp__ra2__*`），stdio 起 `python3 -m ra2agent.mcp`，`cwd` 与 `PYTHONPATH` 指向本仓库，`failOnStartupError` 让探针失败当场报错而不是静默少几个工具。

**协议版本坑**：DSH 用的 MCP SDK 只认 `2026-07-28` 与 `2025-11-25`；它走 legacy 握手
时 offer 后者，并要求服务端回的版本**也在 pre-2026 列表里**。手写服务端若在认不出请求
版本时回落 `2026-07-28`，连接会被拒（`Server's protocol version is not supported`）。
故回落值必须是 `2025-11-25`（`FALLBACK_PROTOCOL`）。

## 挂载验证

真模型上桌过一次（当时的临时 profile 已删）：模型自己读局势、看卡片，算出两辆 Grizzly 各东移 6 格的目标格，分两条任务下达，跟进两次 `status`，最后汇报两条 `satisfied`。我们这边核对：两辆车确实停在 (112,60) 与 (116,60)——正是它算的格。

这次也暴露了一处缺口并当场补上：**`status` 原本只给数量不给位置**，模型无从指定落点；现在列出每个单位的 id、名字、所在格与是否在管。同时给 `call` 加了租约检查：已被别的任务占住的单位不再受理，要改派先撤销。

preset 挂载本身验过的：`install_bundle` 返回 `application: applied` 且无告警；`--dump-config` 里 `preset-ra2` 带着 `mcp-ra2` 子条目；loader 里 `include:preset-ra2` 为 `active`；DSH 进程下确实挂着一个 `python3 -m ra2agent.mcp`，cwd 与 `PYTHONPATH` 都对，stdin/stdout 接在 JSON-RPC 管道上。

`game` 验过的：真 stdio 会话里 `game status` 报出「未运行 + 崩溃报告 2 小时前」；`game stop` 在没游戏时报「无需停止」；`status` 连不上时给的是那句人话，不再是 `ConnectionRefusedError`。

## 未做

- `game start`、`focus`，以及对局中的 `stop`，还没在真机上跑过：起游戏会抢焦点并常驻连接，要人看着跑。
- `status` 里不含任何建议：选什么打法由模型自己看局势与卡片决定，指挥层不给策略。
- 落点集的两项未实测，决定缓存能留多久与「忙」的判据：同一栋建筑连查两帧的合法格集合是否一致；放置完成后 `Factory.progress_timer` 是否归零。
