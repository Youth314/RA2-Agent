# 平台与引擎选型

## 结论

引擎用 **ra2yrcpp** 注入原版《尤里的复仇》的 `gamemd.exe`。游戏侧运行环境位于 `D:\Games\ra2probe\`。

## 运行环境

| 项 | 值 |
|---|---|
| 原版安装（只读） | `D:\steam\steamapps\common\Command & Conquer Red Alert II`，Steam 版，1.9 GB |
| 探针环境 | `D:\Games\ra2probe\`，MIX 文件硬链接至原版，可执行文件与配置独立复制 |
| 建环境脚本 | `.agents/tmp/setup-game-env.sh <源目录> <目标目录>`，可反复重建 |
| 项目位置 | WSL 的 `~/ra2-agent`；游戏必须在 Windows 运行，经 `/mnt/d` 访问 |
| Windows Python | `D:\Anaconda3\python.exe`，含 `google.protobuf` 与 `websocket-client` |

Steam 版是干净原版：`gamemd.exe` 的 PE 时间戳为 2001-10-31，`ra2.mix`(281,888,480) 与 `ra2md.mix`(204,527,696) 与另外两份独立安装逐字节相同。

## 选它的理由

1. 它是唯一提供真引擎完整状态与命令通道的现成方案，协议为 protobuf over TCP/WebSocket。
2. 遭遇战的所有玩家在同一 `gamemd.exe` 进程内，玩家类型与迷雾由引擎处理，天然支持玩家 / Agent / 内置电脑玩家混合。
3. 提供逐帧状态录制（`recordFilename`）与单步模式（`singleStep`）。

## 放弃的方案

| 方案 | 理由 |
|---|---|
| Chrono Divide | 非原版引擎；真人参与需其线上服务与 API key |
| 截屏 + 模拟输入 | 慢且脆弱；ra2yrcpp 已提供结构化接口 |
| OpenRA | 非原版规则 |
| Ares / Phobos | modding 平台，由 INI 驱动，不提供外部接口 |
| 自写引擎扩展 | 工作量远超项目本身；ra2yrcpp 已是该形态的现成实现 |

## 硬约束

- 只支持《尤里的复仇》（`gamemd.exe`），不支持原版红警2（`game.exe`）。
- 必须 patch `gamemd-spawn.exe`；patch `gamemd.exe` 会崩溃。
- 运行需要 `spawn.ini` 与 `spawnmap.ini`，缺一则 `-SPAWN` 模式开始对局时崩溃。
- ra2yrcpp 及其依赖（YRpp、CnCNet spawner）均为 GPL-3.0。
