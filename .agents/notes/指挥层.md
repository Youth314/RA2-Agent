# 指挥层

模型与技法层之间的那道门。实现见 `src/ra2agent/command.py`。

## 形态

**工具数固定，能力数随技法库增长。** 技法从 5 条长到 200 条，模型看到的永远只有四个工具；库里有什么写在卡片上，不在工具名上。

| 工具 | 做什么 | 返回 |
|---|---|---|
| `status` | 读局势：一行摘要、在管任务、上次读过之后的新结果与告警 | 文本 |
| `tactics` | 读卡片：此刻用得上的技法，可按关键词筛 | 若干行 |
| `call` | 下达一到多条任务，**立刻返回不等待** | 每条一行受理结果 |
| `cancel` | 撤销在管任务，交还它占用的单位 | 每条一行 |

`call` 不等生效：等待是技法层的活。受理也不等于成功——成功与否由下一次 `status` 报。

## 受理时就把话说清楚

`call` 会做一遍技法层同样的校验，任一项不过就当场拒绝并说明原因，而不是让它静默空转：

| 拒绝原因 | 例子 |
|---|---|
| 没有这条技法 | 名字拼错 |
| 零件不对指挥层开放 | `halt` 只能被组合技法调用 |
| 等级超出门槛或已被停用 | `exploit` 档默认关 |
| 此刻用不上 | 视野里没有敌人却调接战技法 |
| 参数不对 | 缺 `cell`、多给了不认识的字段 |
| 单位不对 | 不是你方可用单位 |

批量下达每条独立受理，允许部分成功。

## 事件只报一次

`status` 报「上次读过之后」新结算的任务和运行时告警（失焦暂停、条件变化导致空转），读走即清空，免得模型每拍重看同一批。在管任务每次都报，不消耗。

报告形状固定，便于模型比较两次之间的变化，也便于日后复盘。

## 可见面

| 模式 | 模型能看见 | 能做什么 |
|---|---|---|
| 对战 | 四个工具与卡片 | 下达指挥层意图 |
| 离线 | 卡片加零件的完整清单、L0 的 API 与源码 | 写与验证技法 |

对战模式看不到零件、看不到技法源码、看不到原始帧（单帧 11.9 KB，只给摘要），也**没有任何直接发引擎命令的工具**——这是安全底线：一切动作都得经过技法层与 `Validator`。

## 两条约束

- **暂停时不下令。** 失焦期间排队的命令恢复后照常执行，那时已脱离下令时的语境。`MicroLayer.run()` 按帧节流自动避免；直接调 `tick()` 没有这层保护。
- **唤醒节奏由模型自己安排。** 有在飞任务就短看，空闲就长看；主动推送（不等模型问就叫醒）暂不做。

## 真机验证

假模型脚本对着真局跑过一轮，四个工具都验了：

| 验的 | 结果 |
|---|---|
| `status` / `tactics` | 文本可读，卡片按局面筛（无敌人时接战技法不出现） |
| `call` 受理 | 两辆车推进到 6 格外，两拍后 `satisfied`，到位 2；命令 3 帧生效 |
| `call` 拒绝 | 无敌人调接战报「此刻用不上：has_enemies」；伪造单位 id 报「不是你方可用单位」 |
| `call` 参数取值 | `cell: null` 当场报「取值不合法」，不再等技法里抛 TypeError |
| TTL | 60 帧的任务按约到期，结算记 `expired`，不计到位 |
| `cancel` | 随即撤销，结算记 `superseded`，到位 0 |

**参数取值必须在受理时校验**：只查「在不在」时，`cell: null` 会一路走到技法里才抛
TypeError——异常隔离兜得住，但模型拿到的是一句看不懂的报错。`Param` 因此加了
`check` 字段，内置 `is_cell`、`is_stance`、`is_non_negative_int`、`is_positive_number`。

## 挂载方式

**当前形态**：一个 agent preset `ra2`，声明在 [dsh/](../../dsh/)。选中它的会话同时具备原有编码能力与四个游戏工具，即目标形态的那个「一个 Agent」。

**技法 skill 不接线**：`skill-filesystem` 扫会话项目根下的 `.agents/skills`，故会话 cwd 落在 `~/ra2-agent` 时 `ra2-write-tactic` 自动出现，卡片里的相对链接也指向仓库内的真实文件。

**为何是 preset 而非 profile 级 insert**：profile 级会让每个会话都常驻一个 MCP 进程，而一个进程独占游戏连接；preset 只影响选中它的会话。代价是 preset 的 `plugins` 是完整清单、不能引用别的 preset，故 `ra2` 整份抄自 DSH 自带的 `cordis`，DSH 升级不会自动跟进——用 `python3 dsh/generate.py --check` 查同步。

**安装**：`plugin_manager` 的 `install_bundle`，目标写 `/home/youthz/ra2-agent/dsh`；它把该 bundle 加进 `~/.dsh/profiles/web/package.json` 的 `dependencies` 与 `dsh.profile.bundles`，profile 的 patch 文件不用手改。

**选用**：GUI 的 General 设置里把默认 preset 设为 `ra2`，或新建会话时选它；已在跑的会话保持它启动时的 preset。

## 接入 DSH

Python 侧是 MCP 服务（`src/ra2agent/mcp.py`，JSON-RPC over stdio，只用标准库）：

- **启动时不连游戏**：DSH 会先用临时探针进程列工具，那时游戏可能没开。连接在第一次
  调用工具时建立，随后由后台线程按约 2 Hz 推进技法层。
- **`call` 立刻返回**，不等生效——单次工具调用默认 60 秒超时，等待是技法层的活。
- **连上就不撒手**：进程活着期间一直握着游戏连接（`GameSession.close()` 只在进程退出时调），故模型用过一次工具后，`tools/` 下的直连脚本要等 DSH 退出才能连上。
- stdout 只放协议消息，日志走 stderr。

DSH 侧是 `dsh/cordis.patch.yml` 里 preset `ra2` 的一条子条目 `mcp-ra2`，挂的是已装的 `@deepseek-ai/dsh-mcp-client`：`serverName` 取 `ra2`（工具名因此是 `mcp__ra2__*`），stdio 起 `python3 -m ra2agent.mcp`，`cwd` 与 `PYTHONPATH` 指向本仓库，`failOnStartupError` 让探针失败当场报错而不是静默少四个工具。

**协议版本坑**：DSH 用的 MCP SDK 只认 `2026-07-28` 与 `2025-11-25`；它走 legacy 握手
时 offer 后者，并要求服务端回的版本**也在 pre-2026 列表里**。手写服务端若在认不出请求
版本时回落 `2026-07-28`，连接会被拒（`Server's protocol version is not supported`）。
故回落值必须是 `2025-11-25`（`FALLBACK_PROTOCOL`）。

## 真机验证

真模型上桌过一次（当时的临时 profile 已删）：模型自己读局势、看卡片，算出两辆 Grizzly 各东移 6 格的目标格，分两条任务下达，跟进两次 `status`，最后汇报两条 `satisfied`。我们这边核对：两辆车确实停在 (112,60) 与 (116,60)——正是它算的格。

这次也暴露了一处缺口并当场补上：**`status` 原本只给数量不给位置**，模型无从指定落点；现在列出每个单位的 id、名字、所在格与是否在管。同时给 `call` 加了租约检查：已被别的任务占住的单位不再受理，要改派先撤销。

preset 挂载本身验过的：`install_bundle` 返回 `application: applied` 且无告警；`--dump-config` 里 `preset-ra2` 带着 `mcp-ra2` 子条目；loader 里 `include:preset-ra2` 为 `active`；DSH 进程下确实挂着一个 `python3 -m ra2agent.mcp`，cwd 与 `PYTHONPATH` 都对，stdin/stdout 接在 JSON-RPC 管道上。
