# U06 / U07 对象警戒接口方案

日期：2026-10-03。状态：离线源码方案已准备；协议、Python、DLL 源码及构建尚未实施，待用户按本文范围确认。部署、宿主重启、配置和游戏动作另获批次授权；本文不是执行授权或验证结果。来源及开发顺序见[建设计划](../../notes/设计/玩家操作接口建设计划.md)，未覆盖项见[矩阵](L1基础接口契约与现状审计.md#a0-玩家能力覆盖矩阵)。

## 1. 范围与既有证据

U06 对应 EscortUnit：单个己方车辆点名另一己方车辆；U07 对应 GuardStructure：单个己方车辆点名己方建筑。模型仅通过 escort_unit / guard_structure 薄技法调用，units 为单个 actor Agent ID，params.target 为目标 Agent ID；不允许自行传 pointer、native ID、Mission、Cell 或网络事件。DLL 首版接受单车辆，效果验证先限定 MTNK；其他车辆的原生语义可能不同，不据此声称支持其护送、维修或装载效果。步兵 / 飞机 / 盟友 / 敌方 / 中立目标、批量 actor 与强制修饰保留 unsupported，拒绝 actor 自身作为目标。

复用[能力表 T02](../../notes/引擎/玩家操作能力表.md#s2-现场记录)的人工证据：单位护送和建筑保护均由 AREA_GUARD / 对象 Target 输入建立，follow 与 destination 的 RTTI 均为 0；单位护送中目标移动后 actor 自行追随，未向 actor 另下移动令。该证据不证明新增 DLL 分支，建筑仅证明输入与靠近，无敌人下的轨迹不证明作战保护。维修 FV 的上下文输入可能是 ATTACK，不能套用本组 AREA_GUARD。

## 2. 固定源码结论

已只读核对本地基线：ra2yrcpp ee215f5a01f709c52b1fe4dd333d16cbe5d5f146、ra2yrproto 0ad72455bcdcf5626d0e17c3311ea82556da2ad3、YRpp 173447cf75f5175e5c6530a439fbadc106ea6a6f。独立源码和编译依赖复用[构建准备](../../notes/环境/DLL构建准备.md)，不下载 / 安装新依赖，不修改干净基线或既有 feature 产物。

现有 UnitOrderCtx::guard 明确拒绝 target_object，13 / 14 只接收当前位置或合法 Cell；不能直接向旧 guard_order 添加对象参数。新增独立分支沿用受控 actor / 时效检查，在游戏线程从 TechnoClass::Array 按指针值查目标，再核对 UniqueID、Owner 和 WhatAmI。成功后拟调用已有固定 ABI ClickMission(actor, Mission::Area_Guard, checked_object, nullptr, nullptr)；返回 false 明确拒绝，不走 get_object_entry 的旧坐标缓存，不调用通用 MissionClicked 或自行写 Target。

TechnoClass.h 的 Target 标注为攻击对象；FootClass 的 Destination 可指对象，但当前 state_parser 只在其为 Cell 时填坐标。T02 护送记录中的 destination 还保持旧地点，现有资料不足以确认专用护送关系字段。本批不新增“护送目标”回读、不要求 TechnoClass::Target 等于所选对象，不用 destination、Mission 或非零 follow 代替护送关系。U08 实际攻击 Target 的合法只读契约与兼容保持原义。

## 4. 输入确认与生命周期

GuardObject 的观察判据复用 Guard 新输入思路：只接受依据帧之后新出现、未在基线事件集合中的 MegaMission(event_type=4)，匹配当前玩家 house_index、actor RTTI=52 / native ID、Mission_Area_Guard=11、对象 target RTTI=52 / native ID，并确认 destination / follow 为空、不是 planning。建筑具体类型是 6，而事件对象引用 RTTI 为 52，二者不可混用。完整 actor / target 绑定在判据执行时仍须匹配；旧事件、Cell Target、另一对象、另一玩家、旧身份或不完整 oneof 均不能成功。

回执使用 observed_match / native_input_observed，observations 至少包含 native_input=observed、input_observed_frame / input_event_frame 和目标类别；它只证明本次对象警戒输入被观察，不证明游戏已经执行、已经跟随、保护成功或专用持续关系存在。队列 out / do 的多次采样为同一输入，不计为多次命令；is_executed 或事件自身未来 frame 不单独作效果判据。事件没有 request_id，仍受单写入者与采样窗口关联限制。

两个薄技法均为单次操作：输入确认后以 operation_observed 结算、释放 actor 租约，原生行为可继续，L1 不逐拍重发。目标的普通移动不需重复命令；输入确认后的目标死亡、变身、归属变化与原生接敌效果不由薄技法承诺处理。需要长期保持租约或重建护送关系时另设组合技法，不在本批制造持续守卫成功声明。unknown / unverified 继续保留待回读计划，不盲重发；cancel 仅结束 Agent 任务，不发 Stop，不把目标列为控制对象或夺取其租约。

## 6. 候选集中真机与部署方案（未授权、不可直接执行）

通过用户转交独立测试协调者；先固定 Python revision / DLL manifest，再给用户完整批次一次确认。仅使用 Beta 真实玩家，通过正式技法操作；开发 / 主持侧只读取证。原配置起一局，准备 Beta 两台普通 MTNK（A 为 actor，B 为单位目标）及己方既有 GACNST（C 为建筑目标），已有对象 / 生产队列复用。确需准备时，授权需包含完整生产 / 放置和这两台 MTNK，不沿用旧“只造一台”的 Attack 批次范围。自动开局 / 经济与显式请求分开登记。

同局两个正例，各一次新接口输入：先让 A 通过 escort_unit 指向 B，取得新对象警戒输入和玩家一次结算；随后只让 B 用 advance_to_cell(passive, spread=0) 移至预先核对的已探索、可通行、无敌压力地点，记录 A 在无后续命令下的跟随轨迹。再让 A 通过 guard_structure 指向当前合法 C，记录新输入和从与 C 有明显距离的位置靠近建筑的轨迹。两段输入与效果分别裁决；范围只承诺所用 MTNK 的限定表现。没有专用关系字段时记未提供；不把实际攻击 Target 为空认定护送失败，不要求靠近后精确占据建筑格或宣称作战保护。

不重新做原版 Ctrl+Alt 人工测绘、旧 G / S / AttackTarget 正例、旧空 Target 加载对照或完整联机矩阵。加载新 object_guard 版本、身份及当时环境属于本批必要前置。服务端固定拒绝若离线门未能回答关键问题，再单独纳入同一批次明确范围，不默认新增真机故障矩阵。unknown 先回读，无法确认即留证并跳过依赖后续，不重发或另起局补尾窗；停止 / 撤离须事先纳入授权，不能将 cancel 当实际停车。
