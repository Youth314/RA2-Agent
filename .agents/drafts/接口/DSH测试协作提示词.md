核对 git status/log 和能力：你是否能访问仓库、Windows 游戏实例及真实 DSH 主持工具。缺哪个就明确报告，提供用户可执行的短指令；不能用普通 subagent 冒充玩家，也不能直接 Client 下单位命令。现有空壳 package-lock.json 是既有文件，不改、不提交。

开发可能并行推进。开始测试前接收或确定待测包：明确源码 revision、DLL 产物/指纹、任务、所需工具输出、授权和回滚基线。测试使用固定版本；可在告知路径和原因后建立独立 worktree，避免新的 MCP 启动或重连混入主开发未交付的修改。不要 checkout/reset 主工作区，不改 src/、tests/、技法、协议或 DLL 源码，不替开发 agent 修实现。若无法隔离，先明确排除版本混用，再启动玩家进程；记录不明时报告无法确认。

你可以提前说明后在 .agents/tmp/ 下自己的批次目录保存必要脚本、日志和结果。不修改共用的临时部署脚本、长期配置或跟开发 agent 并发编辑 notes / 交接；最终把报告和路径交回，由主开发 agent 统一回写唯一验证记录。无需主开发 agent 逐步审批已授权动作。

这些是候选待测任务，不能直接执行。先将一个具体批次的目的、固定版本、环境改动、全部生产/放置/移动/攻击/人工操作、采集、结束条件和回滚给用户一次确认。委派此协调角色不等于批准新批次；先前批次已经结束，不能继承旧动作授权。配置改动、长期部署和 fault 注入均不在默认范围。若用户已批准该批次，同范围不重复询问，不逐栋申请权限。

### 4. DSH 与操作约束

DSH 主持会话只通过真实 play_as_beta 派 Beta；有同一个仍可用的真实 Beta 时继续它，不并行派两个写入者。禁止派 Alpha、调用上层 Alpha 的 status/tactics/call 或用主持私有身份帮 Beta 选目标。主持侧只读取证与管理已授权启动/收尾。

真实 Beta 模型游戏动作只调用正式技法。完整准备若已纳入授权，可通过 build_structure / place_ready_building / train_unit 补齐 GAPOWR、GAPILE、GAREFN、GAWEAP 并只造一台 MTNK；已有、在队列或待放对象复用。units 使用 Beta 自读的己方建造厂/生产厂 ID，不能用待放建筑 ID；放置省略 cell，由 L0 查询合法格。必要普通移动和人工揭图要包含在批次范围，不能临时扩展生产 Scout 或无关单位。

每次先读自己的 status/tactics，用本局当前合法 Agent ID；新局、断连或标识表重建后不沿用旧号。每项未知操作只提交一次；unknown/unverified 保留回读，不盲重发；cancel 不发 Stop。在管 0 项不等于原生单位停止接战，停止攻击的人工撤离步骤须预先包含在授权及操作单。既有自动开局/经济行为和本次显式请求分别记录，来源不明就记来源未确认。

### 5. 环境、取证与收尾

任何本机改动提前说明改什么、在哪里、为什么。新 DLL/配置和新游戏批次按上述完整范围取得确认。复核当前两侧 DLL SHA-256 / samefile、进程与探针端口、配置指纹；这是防止误替换或混局的必要前置，不是重跑旧功能测试。上次收尾状态不能代替当前现场。

需要 Attack 时复用已经构建的产物与已验证部署/收尾流程，产物位置和指纹从 Attack 验证读取。回滚基线是实际 Stop v1，不能调用恢复 Guard 的旧硬编码脚本。临时部署持久备份 Stop、保留两侧硬链接和独立清单；旧 Stop installed 清单不改。用原配置的 MatchHost.launch 起两侧，不调用会渲染配置的 render/up；实际 Alpha 为 Alliance/AMCV、Beta 为 Americans，不沿用旧 Russians/SMCV 假定。

准备低频读，单位、合法目标和人工步骤就绪后才启动短高频采集。短采集先重新读取地图，避免低频准备漏掉探索增量。复用已有只读采集，不建设新测试平台、成套脚本测试或完整矩阵。单车单目标场景拿到新输入与实际 Target 双证据即停；Mission、事件 is_executed、单个成功返回或健康变化都不能单独替代它们。

分开记录玩家合法工具输出与主持技术取证；前者只含实际提供的字段，后者可在诊断记录中核对原生身份，不将地址/隐藏信息交给玩家选目标。相同事件 out/do 的多次采样不是多次下令。错过窗口、采样不足或缺字段记无法确认/未执行，不扩大支持声明。

结束时关闭本批采集/连接，只按本批 PID 且重查 executable path / creation time 停进程；恢复 Stop v1，核对两侧 SHA / samefile、端口关闭、配置指纹一致和临时清单 rolled_back。意外结束也必须完成已授权收尾。不得按进程名全杀或误伤其他局。

### 6. 一次回报格式

请给用户可转回主开发 agent 的简短报告，包含：

- 批次、源码 revision / DLL 指纹、授权范围及实际玩家通道。
- 每项问题：通过 / 失败 / 未执行 / 无法确认，附最低必要帧号或证据路径；区分工具实读、主持观测和代码推断。
- 请求参数、一次受理回执、最终结果、提供的完成依据；字段缺失明确记未提供，unknown 是否保留、是否重发/取消。
- 单位和目标的本局身份、合法可见性、前后 Target；人工展开若未纳入或错过不算通过。
- 现场恢复：本批 PID 已停、端口已关闭、Stop SHA / samefile、配置一致、清单状态。
- 新缺陷的最小事实与限制，不顺手修源码、不补完所有矩阵。

已回答问题就结束，将报告和证据目录交给用户。不要在已完成项上连续发无变化报告，也不要把每个中间状态都转交主开发 agent。发生故障及时说明并安全收尾，未取得用户确认不启动替代批次。
