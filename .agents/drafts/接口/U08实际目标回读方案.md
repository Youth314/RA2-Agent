## schema 与四种结果

新增 `Object.actual_target = 22`，消息包装保证 presence；新增 `GameState.target_observation_version = 19`，v1 表示支持本方案的有限观测。新号已核对既有补丁，无冲突。Guard/Stop 版本仍为 1，各自含义不变；target_observation_version 不声明受控 Attack 已实现。

```proto
message ActualTargetObservation {
  enum Status {
    STATUS_UNSPECIFIED = 0;
    STATUS_UNOBSERVABLE = 1;
    STATUS_NONE = 2;
    STATUS_OBJECT = 3;
  }
  Status status = 1;
  TargetClass reference = 2;
  AbstractType object_type = 3;
  uint32 object_pointer = 4;
}
// Object 内新增：ActualTargetObservation actual_target = 22;
// GameState 内新增：uint32 target_observation_version = 19;
```

| wire/观测结果 | Python/L1 含义 | 合法用途 |
|---|---|---|
| 版本缺失/0，或 Object 字段 22 缺失 | not_provided；解析层以 None 保留缺失 | 旧 DLL、旧录制均可读取；不能当成无目标 |
| UNOBSERVABLE，其他载荷为空 | unobservable | 不能确认目标，不能据此判攻击失败或目标死亡 |
| NONE，其他载荷为空 | none | 本帧合格己方 actor 的 Target 为 nullptr；不说明过去或下一帧状态 |
| OBJECT，引用/具体类型/同帧对象映射均合法 | object | 本帧当前目标；不等于新输入、射程内、开火或击毁 |

UNSPECIFIED、未知状态、错误 wire、OBJECT 缺载荷、NONE/UNOBSERVABLE 携带引用等不完整组合应按协议错误或无法确认处理，绝不转成 none/object 成功。旧 DLL 即使收到新解析器也不降级使用 Mission.ATTACK 来确认指定目标。

首版只表达 Unit/Infantry/Building/Aircraft 对象目标。Cell、其他 Abstract 子类、失效引用及合法性不能确认的值统一为 UNOBSERVABLE，不导出隐藏类型、位置、native ID、指针或区别原因。后续 ForceFire 的 Cell 目标另立范围；`LastTarget`、`Destination`、`Follow` 不替代当前 Target。

## DLL 采集、编码与可见性门

1. 在游戏线程构建同帧 TechnoClass::Array 成员索引，复用现有 `parse_Objects`；先清理复用 protobuf 槽位的新字段，再解析对象，最后填目标引用。每帧重建索引，不跨帧缓存裸指针。现有 catch(...) 不是非法内存访问的安全证明。
2. 仅为当前 HouseClass::CurrentPlayer 所有、在场、存活、非 limbo 的 actor 读取 Target；外方 actor 一律不提供该字段，即使外方 actor 可见也不读取其 Target。己方建筑/步兵/飞机读取布局不等于承诺对应 Attack 操作可执行。
3. Target 为 nullptr 时填 NONE。非空时先以指针值查本帧存活 Techno 成员索引；未找到则 UNOBSERVABLE，不对未知地址调用 WhatAmI 或访问其成员。通过成员门后才复用 `abi::AbstractClass_WhatAmI::call(c.abi, ...)` 取具体类型，用 `AbstractClass::UniqueID` 取 native ID，禁止直接 Fetch_ID 虚调用或把 pointer/array_index 当 native ID。
4. 原版 TargetClass 的对象引用使用 `m_RTTI=52`（Abstract）、`m_ID=UniqueID`；WhatAmI 返回的 Unit=1/Infantry=15/Building=6/Aircraft=2 单独填 object_type。构造 TargetClass 的两个成员后复用 `parse_TargetClass` 填 reference，不直接调用其固定地址构造函数。DWORD→int32 保留 32 位模式，Python 解析后按 uint32 归一化作身份比较；NativeTarget 的既有事件语义不改。
5. object_pointer 仅作本帧对象与 Agent 稳定 ID 的内部映射，复用现有 pointer_self/IdentityTable；只有目标通过合法信息门才填写。它与 reference、object_type 来自同一成员记录，不暴露给模型、不作为长期身份或新地址工具。外方 `Object.native_id=21` 继续不提供，避免无关扩展。
6. 己方合法在场目标可读。外方首版仅考虑实际 `FogOfWar=No`、目标格未 shrouded、在场存活且普通未隐形/未伪装的对象；配置、场景标志或隐形/伪装状态不能可靠核对时返回 UNOBSERVABLE。FogOfWar=Yes 的外方目标一律不可观测，直到精确当前视野另立验证范围。不能以 DiscoveredByCurrentPlayer（已发现）或 ObjectClass::IsVisible（视口绘制标记）证明玩家当前可见性；也不能读取对侧状态补齐 L1 目标。

可见性门复用既有地图/shrouded 来源，并核对锁定 YRpp 的 Scenario、Rules、Session FogOfWar、Techno 隐形/伪装成员及偏移；客户端和 DLL 不确定时均保守收敛。布局与离线策略结果见[U08 验证](../../notes/验证/U08实际目标回读验证.md)，尚未完成运行验证，不把灰雾、隐形和伪装支持登记为完成。

## Python 与使用方边界

`engine/state.py` 增加只读目标包装与版本解析；保留 absent，严格校验状态与身份字段。Observer 在每帧先取得合法对象集合，再将己方 actual_target 投影为 `Observation.actual_targets[actor_agent_id] -> ObservedTarget(status, agent_id)`；目标缺席、死亡、变身、指针复用、无法映射或可见性不确定时降为 unobservable，不能凭 IdentityTable 的宽限期复活旧目标，也不能从 Observation.state 兜底泄露隐藏对象。Observation 内所有 GameObject 的原始 actual_target 移除，L1 通过稳定 ID 映射读取目标。

`reference.m_id` 的 native ID 不等于 Agent ID。同帧 pointer/type 映射之外，己方目标还核对 native_id；外方目标由 DLL 同帧成员记录保证引用与对象一致，当前跨帧外方 native 身份能力仍有限，不承诺跨局身份。未来目标由可见变为隐藏时立即撤掉当前引用，不保留随隐藏对象更新的实时信息。

本切片先交付观测与合法投影，不改变 Executor 当前 Attack 判官、不增加攻击工具、不重构 focus_fire/guard_area。后续 U08 受控 Attack 还须补目标可见性受理门、服务端身份复查和实际目标匹配；仅 Target 回读完成不能把覆盖矩阵改成 AttackTarget 已可靠。

未来 verify 对 OBJECT 才按所请求目标的同帧身份比对；旧 DLL/不可观测返回未知，原来已是同一目标记 preexisting_match，发送后改成指定目标才可记 state_changed。以上状态匹配均不冒充 native_input_observed，不自动重发未知请求；开火和目标健康变化是独立效果证据。
