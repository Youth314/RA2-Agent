# 相似项目调研

调研日期：2026-10-01。通过 GitHub MCP 搜索仓库，并阅读候选项目的 `README.md`；下述描述以调研时 GitHub 页面与 README 为准。

## 项目需求基线

本项目以 Steam 官方《尤里的复仇》原版为游戏本体，运行 `gamemd.exe`，经 `ra2yrcpp` 取得结构化状态并下发命令；探针环境是与原版安装分离的副本。保持官方原版规则与游戏本体是选型约束，不以重制版、复刻引擎或改写规则的游戏替代。游戏外提供 MCP 工具，由模型决定策略，技法负责可复用动作，运行时负责异步执行、校验、状态反馈与玩家介入。支持 Agent、人和游戏内置电脑玩家混合对战。依据：[平台与引擎选型](../../notes/环境/平台与引擎选型.md)、[架构设计](../../notes/设计/架构设计.md)、[技法框架](../../notes/设计/技法框架.md)、[指挥层](../../notes/设计/指挥层.md)。

## 同类 Agent 接口参考

### [yxc20089/OpenRA-RL](https://github.com/yxc20089/OpenRA-RL)

- 面向 OpenRA 的 AI 对战框架，支持 LLM、脚本 Bot 与 RL agent；Python 环境封装通过 HTTP/WebSocket 与 FastAPI、gRPC 桥和改造后的 OpenRA 引擎通信。
- README 列出 48 个 MCP 工具，覆盖状态查询、静态知识、规划、移动、生产、建筑管理、编组、批量动作与复合计划；工具组可按配置启停。状态包含己方资产、可见敌人、地图张量、经济与可生产项目。
- 与本项目相似处：用结构化状态和动作 API 驱动 RTS；同时提供 MCP 接入和可直接运行的 LLM agent；包含知识查询、地图分析、回放与对局运行管理。
- 适用范围：它是 LLM/Agent 控制 RTS 的完整接口示例，但运行在 OpenRA 引擎与其规则上，不是 Steam 官方《尤里的复仇》；游戏状态、命令效果、地图、阵营和经济规则不能直接移植到本项目。
- 与本项目的关键差异：它改造 OpenRA 引擎并依赖 Docker/Python 包；本项目保持 Steam 官方原版游戏本体，经 `ra2yrcpp` 接入。它暴露较细的游戏工具和 Gymnasium/OpenEnv 风格环境，本项目将模型接口收敛为 `status`、`tactics`、`call`、`cancel`、`game`，由技法层封装操作。
- 可借鉴范围限于 Agent 软件接口：工具分类与按需裁剪、地图和静态知识查询、保持最新观测的通道策略、结构化回放和基准评测。其 48 工具表、引擎集成方案和游戏行为不能据此视为本项目的候选实现。

## 同一游戏的接口上游

### [shmocz/ra2yrcpp](https://github.com/shmocz/ra2yrcpp)

- 为《尤里的复仇》进程提供基于 protobuf 的 TCP 接口和 C++/Python 库，可读游戏状态、发送命令，并支持逐帧录制；README 说明其协议设计受 `s2client-api` 启发。
- 与本项目的关系不是平行 Agent 产品：它是本项目选用的引擎接入层，解决游戏进程通信；本项目在其上构建校验、对象标识、意图、技法、MCP 工具和人机协作。
- 可借鉴：持续关注上游协议、构建方式、录制能力与兼容性变更。上游 README 提醒录制文件可能很大，并说明专用 spawner 不兼容 CnCNet 标准版本；本项目已有独立环境与录制约束，详见[平台与引擎选型](../../notes/环境/平台与引擎选型.md)及[探针实验结论](../../notes/引擎/探针实验结论.md)。

### [shmocz/pyra2yr](https://github.com/shmocz/pyra2yr)

- `ra2yrcpp` 的 Python 接口，不是独立 Agent 产品。README 的示例通过两个游戏实例并发执行开局展开和建造流程，并提供 Docker Compose 多局测试环境。
- 与本项目的技术栈和游戏本体最接近；可参考 Python 客户端、并行多实例启动与集成测试组织。README 未显示 MCP/LLM 决策层，也未提供与本项目技法、校验和指挥层等价的实现。

## 原版 YR 的注入、扩展与 AI Mod

### [WolfCTOS/LuaAPI-for-Red-Alert-2](https://github.com/WolfCTOS/LuaAPI-for-Red-Alert-2)

- README/API 文档标明目标是 Yuri's Revenge `1.001` 的 `gamemd.exe`，通过注入的原生 x86 Lua 5.4 与 C++ 安全层暴露游戏对象、查询、移动、攻击、任务状态及逻辑帧回调；项目处于 Beta。
- 这是本次新增候选中与原版游戏运行时交互最接近的研究对象。可参考对象指针安全、短生命周期对象处理、任务回读和帧回调设计。
- 它需要注入 DLL 并加载 Lua gameplay mods，会增加游戏运行时组件；本项目可先借鉴其公开 API 与源码语义，不因此将它作为项目运行依赖。README 标注目标版本为 1.001，但没有明确保证 Steam 安装兼容，需单独核实。

### [AdjWang/RA2YurisRevengeTrainer](https://github.com/AdjWang/RA2YurisRevengeTrainer)

- 面向 YR `1.001` 原版/Ares 的内存修改器，后端 DLL 注入游戏并监听本地端口 `35271`，桌面与网页前端通过该接口同步；README 明确提及 Steam 原版支持，但存在卡顿并给出 CPU affinity 配置建议。
- 可参考游戏内注入、前后端分离、局域网网页控制和 Steam 兼容性经验；其功能包含开图、改钱、无敌等修改器能力，不是公平 Agent 命令接口，不应直接作为本项目控制面。

### [Ares-Developers/YRpp](https://github.com/Ares-Developers/YRpp) 与 [CnCNet/yrpp-spawner](https://github.com/CnCNet/yrpp-spawner)

- `YRpp` 提供与 YR 二进制和数据类型交互的 C++ 头文件；`yrpp-spawner` 是用 Syringe 可加载的 CnCNet 启动器/补丁，负责跳过菜单并依据 `spawn.ini` 配置对局。
- 两者可用于理解原版引擎类型、注入接口和遭遇战启动配置，不提供本项目所需的外部 Agent 决策系统。项目已使用 `ra2yrcpp` 的引擎接入与独立探针目录，无需为了参考这些仓库而替换 Steam 游戏本体或当前启动路径。

### [CrimRecya/YRpp4ida](https://github.com/CrimRecya/YRpp4ida)

- 单个 C 头文件，可加载到 IDA Pro 中解析 YR `gamemd.exe`，包含部分虚表地址；作者说明它不完整，源自公开 YRpp 并经逆向工作扩展。
- 可作为逆向辅助材料，不能视为完整或权威的二进制映射；具体偏移和行为仍须结合本项目目标二进制验证。

### [Ritanlisa/RA2YR_ReSource](https://github.com/Ritanlisa/RA2YR_ReSource)

- 仓库自述为从 `gamemd.exe` 逆向重建的 C++ 源码，目标是逐步形成独立替代引擎；含 IDA 辅助验证和 hook 影子执行框架。
- 对象布局、调用关系和逆向工作流可能有研究价值；其独立替代引擎目标与本项目保持 Steam 官方游戏本体的约束不同，重建代码和实验结论不能直接替代官方 `gamemd.exe` 或未经验证地复制到适配层。

### AI 增强 Mod：只作行为参考

- [mbnq/RA2YRBF](https://github.com/mbnq/RA2YRBF)（Brute Force）README 表示它要求干净的 RA2/YR 安装、支持 EA 与 Steam 版，并通过 Mod Launcher 启动；Mod 会调整 AI 与对局参数。它能提供原版规则下的 AI/遭遇战行为对照，但安装会改动游戏内容，不能并入本项目固定的原版探针环境。
- [Renhuai123/ra2-enhanced](https://github.com/Renhuai123/ra2-enhanced) 是 RA2/YR 的 INI 增强 Mod，README 当前状态为 AI v0 已写、真机 A/B 尚未验证，并依赖 Ares/Phobos。适合观察 `TeamTypes`、`AITriggerTypes` 与规则覆盖组织；由于依赖 Mod 扩展且未实机验证，不作为本项目实际对局方案。
- 清单提到的 `ACBC10 Superior SmartAI` 未通过本次 GitHub 仓库搜索定位到可确认的上游仓库，暂不评价其功能与适配性。

## 网页重实现与替代引擎：Agent 设计参考

### [vibeinging/dsh-red-alert](https://github.com/vibeinging/dsh-red-alert)

- 仓库描述强调“真实红警2引擎”，但其 [`renderer-adapter/README.md`](https://github.com/vibeinging/dsh-red-alert/blob/main/renderer-adapter/README.md) 写明：构建锁定版本的 [huangkaoya/redalert2](https://github.com/huangkaoya/redalert2) React/Three.js 客户端；后者 README 称其为基于 RA2WEB/Chrono Divide 分析开发的 TypeScript 重构。插件从本地导入 `RA2.MIX` 等素材，游戏在浏览器中的兼容客户端运行。
- 因此它不是 Steam 官方 `gamemd.exe`，也不是本项目所说的原生引擎运行实例。清单中“同为原生引擎”这一判断与仓库公开的构建说明不符。
- 其 Agent 部分仍值得参考：阶段化加载工具、批量单位命令、公平视野快照与冻结 last-seen、命令回执携带新状态、基于 episode 的赛后学习，以及 DSH 插件集成。游戏语义、引擎通信和运行时集成都不可直接当作本项目的实现。

### [lukeliu95/ra2-commander](https://github.com/lukeliu95/ra2-commander)

- README 明确目标是 Chrono Divide/王二火大网页重制版；通过浏览器执行层控制游戏，并采用多个 Agent 分工、赛后复盘与战术演化。
- 与本项目的多 Agent 协作和学习闭环有设计相似点，但不是 Steam 官方游戏或 `gamemd.exe` 接口。页面状态提取、动作效果、速度和单位行为都需在原版游戏重新验证。

## 游戏实现差异较大的原型与评测框架

### [LQR86/MinSC](https://github.com/LQR86/MinSC)

- README 将其定位为面向 MCP 的最小 StarCraft RTS 环境；当前实现是 Pygame 原型，含工人、资源采集、指挥中心与生产。
- README 的功能状态明确写出 MCP 三层决策 API、外部 AI 接入、战斗单位和 AI 对战仍待实现。因此它在愿景上相似，当前不能视为可直接采用的 MCP 游戏 Agent 框架。
- 可借鉴：以最小游戏循环验证 Agent 与 RTS 的接口设计；对本项目具体游戏控制能力、引擎接入和多人对战帮助有限。

### [FlowerTailor/LLM-rts](https://github.com/FlowerTailor/LLM-rts)

- 当前 README 将项目描述为受经典 RTS 启发的向量图形游戏，包含采集、建造、生产、战斗、编队和单位行为系统。
- 仓库名含 `LLM`，但 README 展示的是本地游戏与键鼠操作，没有说明 LLM 接口、MCP 服务或 Agent 控制 API；不能仅凭名称认定它已实现 LLM 玩游戏。
- 可借鉴：自研简化 RTS 中的单位行为、编队移动和资源循环原型；与本项目的真实游戏规则和接入层相差较大。

### [SimonLucas/planet-wars-rts](https://github.com/SimonLucas/planet-wars-rts)

- RTS Agent 评测框架，提供全观测与部分观测接口、同步和异步 runner、Docker/Podman 部署及 round-robin 联赛示例。
- 相似点在于多 Agent 对战和观测受限下的评估；游戏规则、动作和引擎与《尤里的复仇》不同，也不以 MCP 或 LLM 工具为核心。
- 可借鉴：为内置技法或策略建立重复对局、跨对手评估和稳定胜率统计。它不能替代本项目的真机验收与游戏回放。

## 调研结论与优先级

Steam 官方原版是本项目的固定前提。按游戏本体与接口兼容性排序，`ra2yrcpp` 与它的 Python 接口 `pyra2yr` 最相关；LuaAPI、YRpp 和 `yrpp-spawner` 可辅助理解原版运行时与启动配置，但会涉及注入或 mod 工具链，适合源码研究而非直接纳入本项目。Mod 项目只提供行为或规则设计参考，不应改变本项目的原版对局环境。

本次检索没有发现同时满足 Steam 官方《尤里的复仇》原版、结构化引擎状态、Agent/MCP 控制和人机混合对局的其他公开项目。`dsh-red-alert` 和 `ra2-commander` 的 Agent 产品形态较完整，但实际运行于浏览器兼容客户端/网页重制版；OpenRA-RL 使用 OpenRA。后续比较应先核实候选项目使用的游戏本体、引擎和规则，再评估接口设计；游戏本体不兼容时，只提取可独立成立的软件接口经验，不把它列为可迁移的游戏实现。

后续若要做差距分析，先对照 `ra2yrcpp`、`pyra2yr` 与本项目的协议、客户端和多实例测试；再将 `dsh-red-alert` 的工具加载、公平观测与学习闭环作为纯 Agent 软件层参考。LuaAPI 可供原版对象与任务语义交叉核验，但必须针对 Steam 版实际使用的二进制验证。本文是搜索草稿，不代表依赖、迁移或架构调整决定。
