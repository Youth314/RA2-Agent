# .agents

与开发 agent 有关的一切内容。读者是 agent。给人看的文档在 [docs/](../docs/AGENTS.md)。

索引链：根 `AGENTS.md` → 本文件 → 具体文档。

## 目录

| 目录 | 用途 |
|---|---|
| `notes/` | 设计、引擎、验证、环境；维护带证据边界的结论、方法和实施计划 |
| `drafts/` | 研究、接口、问题；交接与 TODO 保留根目录，保存待定方案及现场记录 |
| `tmp/` | 临时产物：脚本、截图、日志。可随时删除，不入库 |
| `skills/` | agent skill，格式同 DSH；`ra2-play/` 是打局时读的入口，`ra2-write-tactic/` 是写技法的规范 |

## 写作要求

适用于 `notes/` 与 `docs/`；`drafts/` 与 `tmp/` 不适用。

- 禁用口语
- 精简不失要义：删词前保留每个命题的主体与动作、条件与时序、模态、例外、后果；字数减少本身不是改进
- 同一事实单源记录，别处链接
- 只写当前状态，历史留在 git
- 每段一行（便于 diff）
- **标识符保持英文原样，中文只用于解释**：单位与建筑的英文名、`rulesmd.ini` 的段名与键名（`[MTNK]`、`Verses=`）、ModEnc 与 Fandom 的页标题、引擎返回值，都是跨语言稳定的键——翻了就与语料、游戏、回放日志断开。社区中译不统一（灰熊坦克/灰熊战车、天启/启示录），故任何中文译名都必须有单一出处，否则不写。

## 工作流

改动项目内容前：查相关文档 → 读文件 → 完成后回写文档（修订或新增）。

## 归档与验证约定

稳定原则、可追溯调查和经验方法放 notes；候选契约、原始问题和项目收集放 drafts。待测能力须标明未执行或无法确认，notes 归档不等于实现或实测。相同事实维护一个来源，其余文档链接。

测试采用能回答问题的最小充分方法；不为工程化过度设计体系，不以无头化为前置目标。人工操作、观察或录屏明显提速时，提供步骤与判据并邀请用户协助。具体方法见[能力验证方法](notes/验证/能力验证方法.md)。

执行根 AGENTS.md 的功能组验证约定：新会话先复用已通过的结果，按改动选检查；同组真机问题集中一轮，不把已登记的全部未验边界当成开发前置。

文档移动时同步更新 Markdown 链接、源码注释和索引中的路径；不保留重复正文作为旧路径副本。
